> [!abstract] Коротко
> Итоговая практика раздела: серверная функция создаёт расходную накладную по заказу — проверки входных данных, перенос шапки и строк через `ЗаполнитьЗначенияСвойств`, пересчёт сумм, запись — и чек-лист проверки, включая проведение и повторные вызовы.

## Что собираем?

Сделаем программное создание расходной накладной по заказу. Так мы свяжем ссылки, объекты, табличные части, проверки и запись документа.

Предполагается, что уже существуют:
- `ЗаказКлиента` с реквизитами `Покупатель`, `Договор` и табличной частью `Товары`.
- `РасходнаяНакладная` с реквизитами `Покупатель`, `Договор`, `Основание`, `ИтоговаяСумма` и такой же табличной частью.
- В обеих табличных частях есть `Товар`, `Количество`, `Цена`, `Сумма`.
- Оборотный регистр `Продажи` и алгоритм проведения накладной по [[25. Программная работа с регистрами]].

Для этой практики переносим только товары. Если в базе есть табличная часть услуг, аналогичный перенос добавляем отдельно, а итог считаем по обеим частям.

## Серверная функция

Создаём неглобальный общий модуль `ПродажиСервер`, включаем **"Сервер"** и помещаем туда:
```1C
Функция СоздатьНакладнуюПоЗаказу(СсылкаНаЗаказ) Экспорт

	Если НЕ ЗначениеЗаполнено(СсылкаНаЗаказ) Тогда
		ВызватьИсключение "Заказ не выбран";
	КонецЕсли;

	Заказ = СсылкаНаЗаказ.ПолучитьОбъект();
	Если Заказ.Товары.Количество() = 0 Тогда
		ВызватьИсключение "В заказе нет товаров";
	КонецЕсли;

	Накладная = Документы.РасходнаяНакладная.СоздатьДокумент();
	Накладная.Дата = ТекущаяДатаСеанса();
	Накладная.Покупатель = Заказ.Покупатель;
	Накладная.Договор = Заказ.Договор;
	Накладная.Основание = СсылкаНаЗаказ;

	Для Каждого СтрокаЗаказа Из Заказ.Товары Цикл
		Если СтрокаЗаказа.Количество <= 0 Тогда
			ВызватьИсключение "В заказе есть строка с неположительным количеством";
		КонецЕсли;

		СтрокаНакладной = Накладная.Товары.Добавить();
		ЗаполнитьЗначенияСвойств(СтрокаНакладной, СтрокаЗаказа,
			"Товар,Количество,Цена");
		СтрокаНакладной.Сумма = Окр(СтрокаНакладной.Количество * СтрокаНакладной.Цена, 2);
	КонецЦикла;

	Накладная.ИтоговаяСумма = Накладная.Товары.Итог("Сумма");
	Накладная.Записать(РежимЗаписиДокумента.Запись);

	Возврат Накладная.Ссылка;

КонецФункции
```

Функция получает именно ссылку на `ЗаказКлиента`. В реальном общем интерфейсе дополнительно проверяем тип входного значения. Проверки покупателя, договора и товаров должны также действовать в модуле объекта накладной.

## Запуск

Из серверной процедуры учебной обработки можно вызвать:
```1C
СсылкаНаНакладную = ПродажиСервер.СоздатьНакладнуюПоЗаказу(СсылкаНаЗаказ);
```

Здесь `СсылкаНаЗаказ` должна быть заранее получена из выбранного заказа. Для вызова из формы используем серверный метод формы, а на клиент возвращаем ссылку. Общему модулю в этом варианте не нужен прямой вызов с клиента.

## Что получилось?

Мы прочитали заказ, создали новый объект, перенесли шапку, добавили строки, пересчитали суммы и записали накладную. Ссылка `Основание` сохранила связь с исходным заказом.

Изменение цены в исходном заказе позже не изменит автоматически уже созданную накладную. Это отдельные записанные данные.

> [!warning] Важно
> Пример записывает накладную без проведения. Поэтому движения продаж ещё не создаются. Для следующего шага проводим её через интерфейс и проверяем регистр.

## Проверка

Создаём заказ с двумя строками: 2 штуки по 150 и 3 штуки по 100. Ожидаемый итог накладной - 600.

Затем проверяем:
1. Пустую ссылку на заказ - понятная ошибка, новая накладная не создана.
2. Заказ без товаров - понятная ошибка.
3. Нулевое количество - запись не должна успешно завершаться.
4. Перенос покупателя, договора и основания.
5. Проведение, повторное проведение и отмену проведения накладной.

## Что улучшить самостоятельно

Повторный вызов сейчас создаёт ещё одну накладную. Можно добавить правило поиска существующей накладной по основанию, если по условиям задачи она должна быть только одна. Если допускаются частичные отгрузки, понадобится учёт уже отгруженного количества.

Это разные бизнес-правила. Нельзя запретить все повторные накладные только потому, что в нашем первом примере была одна полная отгрузка.
