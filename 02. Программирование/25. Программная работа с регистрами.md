> [!abstract] Коротко
> **Менеджер записи** — для одной записи независимого регистра сведений. **Набор записей** — для группы записей с отбором (по регистратору или измерениям); запись набора **замещает** записи в области отбора. Последнее значение периодического регистра — `ПолучитьПоследнее()`. В проведении документа движения пишем через коллекцию `Движения`.

## Где выполняется код?

Все примеры этой заметки выполняем **на сервере**. Регистр сначала создаём в Конфигураторе. Программный код обращается к уже существующей структуре.

Для цены используем независимый периодический регистр `ЦеныНоменклатуры` из [[20. Регистры сведений]]: измерение `Номенклатура`, ресурс `Цена`, периодичность в пределах дня.

## Запись одной цены

Менеджер записи подходит для отдельной записи независимого регистра:
```1C
Процедура УстановитьЦену(Товар, ДатаЦены, НоваяЦена) Экспорт

	Если НЕ ЗначениеЗаполнено(Товар) Или НоваяЦена < 0 Тогда
		ВызватьИсключение "Проверьте товар и цену";
	КонецЕсли;

	Запись = РегистрыСведений.ЦеныНоменклатуры.СоздатьМенеджерЗаписи();
	Запись.Период = НачалоДня(ДатаЦены);
	Запись.Номенклатура = Товар;
	Запись.Прочитать();
	Запись.Период = НачалоДня(ДатаЦены);
	Запись.Номенклатура = Товар;
	Запись.Цена = НоваяЦена;
	Запись.Записать();

КонецПроцедуры
```

Сначала задали ключ и прочитали существующие данные. Если запись уже есть, изменяем её цену, сохраняя прочие прочитанные поля. Если нет - создаём запись по этому ключу. Дополнительные обязательные поля тоже нужно заполнить.

Запись новой цены **другим днём** сохраняет историю. Запись тем же днём и для того же товара меняет значение по существующему ключу.

## Цена на дату

Для последнего известного значения на указанную дату:
```1C
Отбор = Новый Структура("Номенклатура", Товар);
ДанныеЦены = РегистрыСведений.ЦеныНоменклатуры.ПолучитьПоследнее(ДатаЦены, Отбор);
Цена = ДанныеЦены.Цена;
```

Результат - структура ресурсов. Метод учитывает записи не позднее указанной даты. Если записей нет, значение числового ресурса будет значением по умолчанию, то есть 0.

> [!warning] Важно
> Так нельзя отличить отсутствие цены от явно записанной нулевой цены. Если это различие важно, отдельно проверяем наличие подходящей записи. Для нашего учебного расчёта можно принять правило, что нулевая цена требует ручной проверки.

## Набор записей

Для работы с несколькими записями используется **набор записей**. Сначала задаём отбор, затем читаем, меняем данные и записываем набор.

Например, прочитаем движения одного документа в регистре накопления:
```1C
Набор = РегистрыНакопления.Продажи.СоздатьНаборЗаписей();
Набор.Отбор.Регистратор.Установить(СсылкаНаНакладную);
Набор.Прочитать();

Сообщить(Набор.Количество());
```

Здесь `СсылкаНаНакладную` должна быть непустой ссылкой на документ-регистратор. Пример только читает движения.

> [!warning] Важно
> Запись набора с замещением заменяет записи в области его отбора. Неправильный или отсутствующий отбор может затронуть больше данных, чем мы ожидали. Пустой набор при замещении может удалить существующие записи этой области.

## Движения документа

В обработчике `ОбработкаПроведения(Отказ, Режим)` модуля объекта документа используем его коллекцию `Движения`:
```1C
Движения.Продажи.Записывать = Истина;

Для Каждого СтрокаТовара Из Товары Цикл
	Движение = Движения.Продажи.Добавить();
	Движение.Период = Дата;
	Движение.Номенклатура = СтрокаТовара.Товар;
	Движение.Контрагент = Покупатель;
	Движение.Количество = СтрокаТовара.Количество;
	Движение.Сумма = СтрокаТовара.Сумма;
КонецЦикла;
```

Фрагмент предназначен для **оборотного** регистра `Продажи` из конспекта. Регистратор привязывается через набор движений документа. Платформа запишет отмеченный набор при успешном завершении проведения.

Для регистра остатков дополнительно задаём направление `ВидДвиженияНакопления.Приход` или `Расход`. Код оборотного регистра нельзя переносить без учёта его вида.

## Что проверять

Проверяем первое проведение, изменение документа и повторное проведение, отмену проведения и отказ по ошибке. Важен итог в базе после операции, а не только отсутствие сообщения об ошибке.

> [!question]- Проверь себя
> 1. Чем опасна запись набора записей без отбора?
> 2. Как получить цену товара на дату без запроса?
> 3. Нужно ли вызывать `Записать()` у `Движения.Продажи` в `ОбработкаПроведения`?
>
> > [!success]- Ответы
> > 1. Замещение затронет весь регистр — можно стереть чужие данные.
> > 2. `РегистрыСведений.ЦеныНоменклатуры.ПолучитьПоследнее(Дата, Новый Структура("Номенклатура", Товар))`.
> > 3. Нет: достаточно `Записывать = Истина`, платформа запишет набор после проведения.
