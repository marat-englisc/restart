> [!abstract] Коротко
> `#Область Имя … #КонецОбласти` группирует код модуля, чтобы его было легко читать и сворачивать. На выполнение и видимость переменных области не влияют. В проектах принят стандартный набор областей: **ПрограммныйИнтерфейс**, **ОбработчикиСобытий**, **СлужебныеПроцедурыИФункции** и др.

## Синтаксис

```1C
#Область ОбработчикиСобытий

Процедура ПередЗаписью(Отказ)
	// ...
КонецПроцедуры

#КонецОбласти
```

Области можно вкладывать друг в друга и сворачивать в редакторе (значок `−` слева). Имя области — идентификатор без пробелов.

## Стандартная структура модулей

Стандарты разработки 1С задают порядок областей. Для **модуля объекта**:

```1C
#Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда

#Область ОписаниеПеременных
// Перем ...
#КонецОбласти

#Область ПрограммныйИнтерфейс
// Экспортные методы, которые вызывают другие модули
#КонецОбласти

#Область ОбработчикиСобытий
// ПередЗаписью, ОбработкаПроведения, ОбработкаПроверкиЗаполнения ...
#КонецОбласти

#Область СлужебныеПроцедурыИФункции
// Вспомогательные неэкспортные методы
#КонецОбласти

#Область Инициализация
// Операторы, которые выполняются при создании экземпляра модуля
#КонецОбласти

#КонецЕсли
```

Для **модуля формы** набор другой:

| Область | Что внутри |
| --- | --- |
| `ОписаниеПеременных` | Переменные модуля формы |
| `ОбработчикиСобытийФормы` | `ПриСозданииНаСервере`, `ПриОткрытии`, `ПередЗаписью`… |
| `ОбработчикиСобытийЭлементовШапкиФормы` | `ПокупательПриИзменении`… |
| `ОбработчикиСобытийЭлементовТаблицыФормы<Имя>` | `ТоварыКоличествоПриИзменении`… |
| `ОбработчикиКомандФормы` | Обработчики команд |
| `СлужебныеПроцедурыИФункции` | Всё вспомогательное |

> [!tip] Где посмотреть шаблон
> Стандарт «Структура модуля» на [ИТС](https://its.1c.ru/db/v8std) и любая типовая конфигурация на БСП — живые примеры правильной разметки.

## Пример: модуль приложения

```1C
#Область ОписаниеПеременных

Перем СтартоваяДата;

#КонецОбласти

#Область ОбработчикиСобытий

Процедура ПриНачалеРаботыСистемы()
	ПосчитатьВозраст();
КонецПроцедуры

#КонецОбласти

#Область СлужебныеПроцедурыИФункции

Асинх Процедура ПосчитатьВозраст()
	ДатаРождения = Ждать ВвестиДатуАсинх(СтартоваяДата, "Ваша дата рождения?");
	Если ДатаРождения = Неопределено Тогда
		Возврат;
	КонецЕсли;
	ВозрастВДнях = ПолучитьВозрастВДнях(ДатаРождения);
	Ждать ПредупреждениеАсинх("Ваш возраст в днях: " + ВозрастВДнях, , "Возраст");
КонецПроцедуры

Функция ПолучитьВозрастВДнях(ДатаРождения)
	Возврат Окр((ТекущаяДата() - ДатаРождения) / 86400, 0);
КонецФункции

#КонецОбласти

#Область Инициализация

СтартоваяДата = '20000101';

#КонецОбласти
```

`ПриНачалеРаботыСистемы` — обработчик платформы, `ПосчитатьВозраст` и `ПолучитьВозрастВДнях` — наши служебные методы. Раздел инициализации выполняется при старте, раньше обработчиков.

> [!warning] Что области НЕ делают
> - Не меняют область видимости переменных.
> - Не определяют, где выполняется код. Область с названием `Сервер` не переносит код на сервер — для этого нужны директивы (`&НаСервере`) и инструкции препроцессора (`#Если Сервер Тогда`), см. [[26. Общие модули и контекст выполнения]].
> - В **общих модулях** нет переменных модуля и раздела инициализации — там только процедуры и функции.

Области необязательны для платформы, но обязательны по стандартам разработки: модуль без разметки на код-ревью вернут.

> [!question]- Проверь себя
> 1. Поместили процедуру в `#Область Сервер`. Будет ли она выполняться на сервере?
> 2. В какой области модуля объекта разместить экспортную функцию для других модулей?
> 3. Где в модуле формы место обработчику `ТоварыЦенаПриИзменении`?
>
> > [!success]- Ответы
> > 1. Нет, области не влияют на выполнение. Нужна директива или инструкция препроцессора.
> > 2. `ПрограммныйИнтерфейс`.
> > 3. `ОбработчикиСобытийЭлементовТаблицыФормыТовары`.
