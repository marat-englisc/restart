> [!abstract] Коротко
> Наборы данных: **Запрос**, **Объект** (готовая таблица значений из кода), **Объединение**. Наборы с разной детализацией связывают на вкладке «Связи наборов данных». Фигурные скобки `{ВЫБРАТЬ …}` — расширение языка запросов для СКД; обычный `Запрос` их не выполняет.

## Когда одного набора мало?

СКД поддерживает наборы **Запрос**, **Объект** и **Объединение**. Для первого отчёта достаточно запроса.

| Набор | Применение |
| --- | --- |
| Запрос | Данные получаем запросом к базе |
| Объект | Программа передаёт готовую коллекцию, например таблицу значений |
| Объединение | Объединяем дочерние наборы с согласованными полями |

Несколько связанных наборов полезны, когда у данных разная детализация: например, одна строка по заказу и отдельный список строк его товаров.

## Связи наборов

На вкладке **Связи наборов данных** добавляем связь, указываем источник, приёмник и поля связи. Пример:

- Набор `Документы`: поле `Накладная`, одна строка на документ.
- Набор `Строки`: поле `Накладная`, несколько товарных строк.
- Связь: `Документы.Накладная` → `Строки.Накладная`.

Имена выходных полей задаём в запросах заранее. Для сложной связи дополнительно настраиваем выражения и параметры согласно задаче.

Не переносим итог шапки в каждую строку товаров для последующего суммирования. Сначала определяем, **в каком наборе и на каком уровне** должен рассчитываться каждый ресурс. Несколько наборов не отменяют опасность неправильной детализации.

## Расширение языка запросов для СКД

В тексте набора можно встретить конструкции в фигурных скобках:

```1C
{ВЫБРАТЬ
    Номенклатура.*,
    Контрагент.*}
```

Это специальная часть языка СКД, например описание полей, доступных для выбора. Это не произвольный текстовый шаблон и не обязательная часть обычного запроса.

Пример выше — **фрагмент расширения**, а не самостоятельный запрос. Имена относятся к полям результата набора. Для первых отчётов используем **Автозаполнение**: СКД сама определит доступные поля.

Если переносим текст из СКД в объект `Запрос`, сначала учитываем расширение: обычный движок запроса не предназначен для выполнения этих директив как есть. Для сложного случая проверяем сформированный запрос компоновки, а не просто удаляем скобки наугад.

> [!question]- Проверь себя
> 1. Когда нужен набор «Объект»?
> 2. Можно ли скопировать текст с `{…}` в объект `Запрос` как есть?
> 3. Почему не стоит переносить итог шапки в каждую строку товаров?
>
> > [!success]- Ответы
> > 1. Когда данные подготовлены кодом (например, таблица значений) и передаются в СКД.
> > 2. Нет, это расширение СКД.
> > 3. При суммировании итог умножится на число строк.
