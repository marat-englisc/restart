> [!abstract] Коротко
> В `ПриКомпоновкеРезультата` модуля отчёта можно вывести отчёт кодом: `КомпоновщикМакетаКомпоновкиДанных.Выполнить(Схема, Настройки)` → `ПроцессорКомпоновкиДанных.Инициализировать(Макет)` → `ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент.Вывести(Процессор)`. `СтандартнаяОбработка = Ложь` отключает автоматический вывод.

## Когда нужен код?

Стандартный отчёт с основной схемой платформа формирует автоматически. Код нужен, например, для подготовки дополнительных данных или управления выводом.

Цепочка: **схема + настройки → макет компоновки → процессор компоновки → процессор вывода**. Макет компоновки здесь — подготовленное задание механизму, а не нарисованная печатная форма.

Вывод в табличный документ выполняет специальный процессор: ему передаём документ методом `УстановитьДокумент()`, затем процессор компоновки методом `Вывести()`. [Руководство разработчика 1С, раздел 10.7](https://1c-dn.com/download-trial/files/guides/developer_guide.pdf).

## Минимальный пример

Открываем **модуль объекта отчёта**. Через список событий создаём обработчик `ПриКомпоновкеРезультата` и помещаем код. Он выполняется на сервере:

```1C
Процедура ПриКомпоновкеРезультата(ДокументРезультат,
    ДанныеРасшифровки, СтандартнаяОбработка)

    СтандартнаяОбработка = Ложь;
    Схема = ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных");
    Настройки = КомпоновщикНастроек.ПолучитьНастройки();

    КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
    Макет = КомпоновщикМакета.Выполнить(
        Схема, Настройки, ДанныеРасшифровки);

    Процессор = Новый ПроцессорКомпоновкиДанных;
    Процессор.Инициализировать(Макет, , ДанныеРасшифровки);

    Вывод = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
    Вывод.УстановитьДокумент(ДокументРезультат);
    Вывод.Вывести(Процессор);

КонецПроцедуры
```

Используем именно имя существующего макета. `КомпоновщикНастроек` — свойство объекта отчёта; берём текущие настройки, чтобы сохранить выбор пользователя. Сигнатуру обработчика получаем из своей платформы, особенно если её версия отличается.

`СтандартнаяОбработка = Ложь` отключает автоматическое формирование: весь вывод теперь выполняет наш код. Для первого отчёта из практики этот обработчик добавлять не требуется.

## Что проверить?

Сначала формируем отчёт стандартно и записываем результат. Затем подключаем обработчик и формируем с тем же периодом и отборами. Должны совпасть строки и суммы.

Для набора **Объект** потребуется отдельно подготовить внешние данные и передать их процессору при инициализации. Для интерактивной расшифровки сохраняем и используем `ДанныеРасшифровки`, а не создаём несвязанную новую структуру после вывода.

Методы и контекст сверяем в Синтакс-помощнике. Здесь не показаны пользовательская форма, экспорт в файл и подготовка внешних наборов — это отдельные расширения работающего отчёта.

> [!question]- Проверь себя
> 1. Что произойдёт, если установить `СтандартнаяОбработка = Ложь` и ничего не вывести?
> 2. Откуда берутся текущие настройки пользователя в коде отчёта?
> 3. Зачем передавать `ДанныеРасшифровки`?
>
> > [!success]- Ответы
> > 1. Отчёт будет пустым — платформа больше ничего не формирует.
> > 2. `КомпоновщикНастроек.ПолучитьНастройки()`.
> > 3. Чтобы работала расшифровка (клик по ячейке отчёта).
