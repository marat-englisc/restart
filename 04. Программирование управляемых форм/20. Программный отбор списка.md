> [!abstract] Коротко
> Отбор динамического списка — элемент `Список.Отбор.Элементы` типа `ЭлементОтбораКомпоновкиДанных`: `ЛевоеЗначение` (`Новый ПолеКомпоновкиДанных("Покупатель")`), `ВидСравнения`, `ПравоеЗначение`, `Использование`. Создаём **свой** элемент один раз и дальше только меняем его значение и `Использование`. Не вызываем `Очистить()` — удалим чужие условия.

Продолжаем `ФормаСпискаУчебная` из темы 19: основной реквизит `Список`, поле `ПокупательОтбор` над таблицей. Для проверки нужны накладные минимум двух покупателей.

## Элемент отбора

| Свойство | Наш пример |
| --- | --- |
| `ЛевоеЗначение` | `Новый ПолеКомпоновкиДанных("Покупатель")` — **имя поля списка**, не синоним и не `Объект.Покупатель` |
| `ВидСравнения` | `ВидСравненияКомпоновкиДанных.Равно` |
| `ПравоеЗначение` | Ссылка из `ПокупательОтбор` |
| `Использование` | `Истина`, если покупатель выбран |

> [!warning] Выключено ≠ равно пустому
> «Показать всех» — `Использование = Ложь`. Включённое равенство пустой ссылке покажет только документы **без** покупателя.

## Код

У поля `ПокупательОтбор` — обработчик **ПриИзменении**, у формы — **ПриСозданииНаСервере**:

```1C
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	УстановитьОтборПокупателя();
КонецПроцедуры

&НаКлиенте
Процедура ПокупательОтборПриИзменении(Элемент)
	УстановитьОтборПокупателя();
КонецПроцедуры

&НаСервере
Процедура УстановитьОтборПокупателя()

	ИмяУсловия = "Покупатель из поля учебной формы";
	НашОтбор = Неопределено;

	Для Каждого Условие Из Список.Отбор.Элементы Цикл
		Если ТипЗнч(Условие) = Тип("ЭлементОтбораКомпоновкиДанных")
			И Условие.Представление = ИмяУсловия Тогда
			НашОтбор = Условие;
			Прервать;
		КонецЕсли;
	КонецЦикла;

	Если НашОтбор = Неопределено Тогда
		НашОтбор = Список.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
		НашОтбор.Представление = ИмяУсловия;
		НашОтбор.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Покупатель");
		НашОтбор.ВидСравнения = ВидСравненияКомпоновкиДанных.Равно;
	КонецЕсли;

	НашОтбор.ПравоеЗначение = ПокупательОтбор;
	НашОтбор.Использование = ЗначениеЗаполнено(ПокупательОтбор);

КонецПроцедуры
```

Первый вызов создаёт условие, следующие — находят и меняют его. Так не накапливаются «= А», «= Б» одновременно (иначе список станет пустым). Тип элемента проверяем, потому что в коллекции бывают **группы** отбора.

> [!tip] В типовых конфигурациях
> Часто встречается `ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбораДинамическогоСписка(...)` — это процедура **БСП**, а не платформы. Без БСП она не заработает. Здесь используем объекты платформы. См. [[05. Профессиональная разработка/09. БСП и типовые конфигурации|БСП и типовые конфигурации]].

## Фиксированные и пользовательские настройки

`Список.Отбор` — **фиксированный** отбор формы. Пользовательские настройки (например, «только проведённые») живут на другом уровне компоновщика и действуют **вместе** с нашим условием. Разница уровней — в [пояснениях к БСП](https://its.1c.ru/db/content/updlib/src/bsp2/2.2/updatessl_2.2.htm).

## Кнопка «Все покупатели»

```1C
&НаКлиенте
Процедура СброситьПокупателяОтбор(Команда)
	ПокупательОтбор = Неопределено;
	УстановитьОтборПокупателя();   // программное присваивание не вызывает ПриИзменении
КонецПроцедуры
```

## Проверка

1. Поле пустое — ограничения нет.
2. Покупатель А → только накладные А; Б → только Б (а не пустой список).
3. Переключаем много раз — число условий не растёт.
4. Пользовательская настройка «Проведён = Да» + «Все покупатели» → проведённые разных покупателей; снова А → проведённые А.

| Симптом | Проверить |
| --- | --- |
| «Поле не найдено» | Есть ли `Покупатель` в полях динамического списка |
| Пусто | Тип ссылки и другие условия |
| Поле меняется, список — нет | Назначен ли `ПриИзменении` |

> [!question]- Проверь себя
> 1. Почему нельзя каждый раз добавлять новый элемент отбора?
> 2. Чем плох `Список.Отбор.Элементы.Очистить()`?
> 3. Как показать всех покупателей?
>
> > [!success]- Ответы
> > 1. Условия накопятся и пересекутся — список опустеет.
> > 2. Удалит условия, которые добавил другой код.
> > 3. `Использование = Ложь` у нашего условия.
