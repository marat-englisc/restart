> [!abstract] Коротко
> **Параметры выбора** — фиксированный отбор (`Отбор.ВидНоменклатуры = Товар`), **связи параметров выбора** — отбор из другого реквизита (`Отбор.Владелец ← Покупатель`). Настраиваем у **реквизита** метаданных — так ограничение действует во всех формах. Режим «Очищать» сбрасывает договор при смене покупателя. Это помощь при вводе, а не контроль данных.

| Свойство | Когда | Пример |
| --- | --- | --- |
| **Параметры выбора** | Значение отбора известно заранее | Только товары |
| **Связи параметров выбора** | Значение берётся из другого реквизита | Договоры выбранного покупателя |

## Подготовка

- `Договоры` подчинён контрагентам (вкладка «Владельцы»), у договора есть `Владелец`.
- У `Номенклатура` есть реквизит `ВидНоменклатуры` типа `ПеречислениеСсылка.ВидыНоменклатуры`.
- Для проверки: два покупателя с договорами, товар и услуга с заполненным видом. На пустом справочнике ограничение не проверить.

## Договор только выбранного покупателя

1. `РасходнаяНакладная → Данные → Договор` → свойства → **Связи параметров выбора**.
2. Имя параметра `Отбор.Владелец`, реквизит `Покупатель`, режим изменения **Очищать**.

Связь работает в форме выбора, быстром выборе и вводе по строке — см. [руководство 1С](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Chapter_5._Configuration_objects/5.4._Common_configuration_object_properties/5.4.17._Choice_parameter_links/?language=en). В форме проверяем, что у поля договора путь `Объект.Договор` и его собственные настройки не противоречат реквизиту. Собственная связь у поля нужна, только если это поле должно вести себя иначе (тогда источник — `Объект.Покупатель`).

«Очищать» срабатывает при **интерактивной** смене покупателя. Если покупателя меняет код — сбрасываем договор сами:

```1C
&НаКлиенте
Процедура УстановитьПокупателя(НовыйПокупатель)
	Если Объект.Покупатель <> НовыйПокупатель Тогда
		Объект.Покупатель = НовыйПокупатель;
		Объект.Договор = ПредопределенноеЗначение("Справочник.Договоры.ПустаяСсылка");
	КонецЕсли;
КонецПроцедуры
```

## Только товары в колонке «Товар»

1. `Товары → Товар` → **Параметры выбора** → `Отбор.ВидНоменклатуры`.
2. Значение — **значение перечисления** `Товар` (не строка «Товар»).
3. Для `Услуги → Услуга` — значение `Услуга`.

Своя форма выбора или произвольная общая форма сама эти параметры не учтёт. Поэтому у поля `ВыбранныйТовар` формы подбора (тема 16) задаём параметр выбора отдельно:

*Параметры выбора у поля `ВыбранныйТовар` общей формы: `Отбор.ВидНоменклатуры` = «Товар».*

## Почему нужна серверная проверка

Обработка может присвоить `Товары[0].Товар` ссылку на услугу, не открывая окно выбора. Обязательные правила — договор принадлежит покупателю, в товарах только товары — проверяем в модуле объекта с `Отказ = Истина`. Отбор в окне выбора не заменяет и права доступа.

## Проверка

1. Покупатель А → выбор договора → только договор А.
2. Меняем на Б → договор очистился → выбор → договор Б.
3. Проверяем и ввод по строке, и быстрый выбор.
4. В товарах нет услуг, в услугах — товаров; подбор тоже фильтрует.

| Симптом | Проверить |
| --- | --- |
| Видны все договоры | Владелец у справочника и у конкретных договоров |
| Не видно ни одного | Заполнен ли покупатель, тип значения |
| Работает в одном поле | Собственные настройки других полей, используемые формы выбора |

> [!question]- Проверь себя
> 1. Нужно показывать только склады выбранной организации документа. Параметры или связи?
> 2. Почему значение параметра выбора — значение перечисления, а не строка?
> 3. Защитит ли параметр выбора от записи услуги в товары обработкой?
>
> > [!success]- Ответы
> > 1. Связи параметров выбора (`Отбор.Владелец` или `Отбор.Организация` ← реквизит `Организация`).
> > 2. Реквизит хранит ссылку на значение перечисления; строка не совпадёт по типу.
> > 3. Нет, нужна проверка в модуле объекта.
