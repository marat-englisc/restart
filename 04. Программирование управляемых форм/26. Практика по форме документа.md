> [!abstract] Коротко
> Практика по темам 01–14: собрать форму расходной накладной с мгновенным пересчётом строк и итога товаров, проверкой ввода в форме, обязательной проверкой и пересчётом в модуле объекта — и доказать, что серверное правило работает и без формы.

Готовые процедуры берём из указанных тем. Уже созданное — проверяем, а не добавляем повторно; промежуточные версии одной процедуры не вставляем подряд.

## Шаг 1. Основа формы

- `Объект` содержит `Покупатель` и `Товары`.
- Пути: покупатель — `Объект.Покупатель`, таблица `Товары` — `Объект.Товары`, колонки `ТоварыКоличество`/`ТоварыЦена`/`ТоварыСумма` — соответствующие поля.
- `ТоварыСумма` — **ТолькоПросмотр**.

## Шаг 2. Итог товаров

Реквизит **формы** `ИтогТоваров` (Число 15,2) → поле ниже таблицы, путь `ИтогТоваров`, ТолькоПросмотр → инициализация в `ПриСозданииНаСервере` ([[10. Пересчёт строк и итога товаров|тема 10]]). Не `Объект.ИтогТоваров`.

## Шаг 3. Расчёт

В модуле формы — по одной процедуре:

| Процедура | Связь |
| --- | --- |
| `ПересчитатьСтрокуТоваров(СтрокаТовара)` | Служебная |
| `ПересчитатьИтогТоваров()` | Служебная |
| `ТоварыКоличествоПриИзменении(Элемент)` | Событие колонки количества |
| `ТоварыЦенаПриИзменении(Элемент)` | Событие колонки цены |
| `ТоварыПослеУдаления(Элемент)` | Событие таблицы |
| `ПересчитатьВсеТовары(Команда)` | Команда «Пересчитать товары» |

## Шаг 4. Проверки

- Форма: `ПроверитьДанныеФормы()` + `ПередЗаписью` формы ([[12. Проверка заполнения и сообщения|тема 12]]).
- Объект: проверка + `ПересчитатьСуммыТоваров()` в существующем `ПередЗаписью` ([[13. Запись из формы и события записи|тема 13]]), услуги и общий итог — сохраняем.

Правила: покупатель выбран, в каждой строке товар, количество > 0, цена ≥ 0.

## Шаг 5. Контрольные числа

| Действие | Строка 1 | Строка 2 | Итог |
| --- | ---: | ---: | ---: |
| 2 × 150 и 3 × 100 | 300 | 300 | 600 |
| Количество строки 1 → 4 | 600 | 300 | 900 |
| «Пересчитать товары» | 600 | 300 | 900 |
| Удалить строку 2 | 600 | — | 600 |
| Удалить строку 1 | — | — | 0 |

Ввод ячейки завершаем `Tab`.

![[УФ-20-Практикум-итог-900.png]]

*Тот же алгоритм в учебной обработке из темы 29: 600 → 900. В накладной вместо текстового наименования — ссылка `Товар`, и при записи работает логика документа.*

## Шаг 6. Отказы и повторное открытие

1. Пустой покупатель → «Записать» → сообщение у поля, запись отменена.
2. Количество 0 → сообщение у количества.
3. Отрицательная цена → отказ.
4. Исправили, записали, переоткрыли → строки на месте, итог 600.
5. Добавили услугу → `ИтогТоваров` — только товары, общий итог учитывает услуги.
6. Точка останова — в `ПередЗаписью` модуля объекта при записи срабатывает.

## Шаг 7. Запись без формы

Клиентский отказ не доказывает серверное правило. Временная команда «Проверить серверное правило» (только в учебной базе, на корректной накладной):

```1C
&НаКлиенте
Процедура ПроверитьЗаписьБезФормы(Команда)
	Сообщить(ПроверитьСерверноеПравило());
КонецПроцедуры

&НаСервере
Функция ПроверитьСерверноеПравило()

	Если НЕ ЗначениеЗаполнено(Объект.Покупатель) Или Объект.Товары.Количество() = 0 Тогда
		Возврат "Заполните покупателя и хотя бы одну строку";
	КонецЕсли;

	ТестовыйДокумент = РеквизитФормыВЗначение("Объект");
	ТестовыйДокумент.Товары[0].Количество = 0;

	НачатьТранзакцию();
	Попытка
		ТестовыйДокумент.Записать(РежимЗаписиДокумента.Запись);
	Исключение
		ТекстОшибки = ОписаниеОшибки();
		ОтменитьТранзакцию();
		Возврат "Запись отклонена (правило работает): " + ТекстОшибки;
	КонецПопытки;

	ОтменитьТранзакцию();   // тестовую запись не сохраняем
	Возврат "ПРАВИЛО НЕ СРАБОТАЛО: объект допустил нулевое количество";

КонецФункции
```

Запись идёт методом **объекта** — события формы не участвуют. Транзакция отменяется в обоих исходах; в форму тестовый объект не возвращаем. Точка останова в проверке модуля объекта должна сработать именно на количестве. После проверки команду убираем. Транзакции — [[02. Программирование/28. Транзакции и блокировки|28. Транзакции и блокировки]].

## Готово, если

- Строки и итог считаются, пустая таблица не ломает форму.
- Ошибки понятны и привязаны к полям.
- Обязательные правила работают и при записи без формы.
- Нет дублей процедур и «потерянных» обработчиков; открытие старого документа не меняет его строки.

**Дополнительно:** флажок `ПоказыватьИтог` из темы 11 — расчёт верен и при скрытом итоге.
