> [!abstract] Коротко
> Большинство ошибок в управляемых формах объясняют три вопроса: **что лежит в переменной** (данные, элемент или объект), **где выполняется код** (клиент или сервер) и **какое событие его запускает**. Ниже — таблица симптомов, шпаргалка по объектам и вопросы для самопроверки.

## Симптом → причина → что проверить

| Симптом | Возможная причина | Что проверить |
| --- | --- | --- |
| Процедура есть, но не вызывается | Не назначена событию | Свойства формы/элемента → События |
| Кнопка ничего не делает | У команды пустое «Действие» | Кнопка → команда → процедура |
| Поле пустое после присваивания | Неверный путь к данным | `ИтогТоваров` или `Объект.Реквизит` |
| «Поле объекта не обнаружено» | Перепутаны данные, элемент, имя | `Объект.Товары` / `Элементы.Товары` / имя реквизита |
| Ошибка при обращении к текущей строке | Строка не выбрана | `ТекущиеДанные = Неопределено` |
| `ТекущиеДанные` на сервере | Интерактивное состояние клиента | Получить на клиенте, передать значения |
| Запрос/ТаблицаЗначений «недоступны» | Клиентский контекст | Серверный метод, реквизит формы |
| Нет `Объект` в функции | `&НаСервереБезКонтекста` | Передать ссылку параметром |
| Сумма строки новая, итог старый | Итог не пересчитан | Порядок «строка → итог» |
| Присваивание не вызвало `ПриИзменении` | Ожидали интерактивное событие | Вызвать расчёт явно |
| Записан документ с ошибкой | Проверка только в форме | Модуль объекта, запись без формы |
| Итог уменьшился после услуг | В общий итог записали товары | Раздельные `ИтогТоваров` и `ИтоговаяСумма` |
| Изменения объекта не видны в форме | Нет обратного преобразования | `ЗначениеВРеквизитФормы(…, "Объект")` |
| Выбор добавляет пустую строку | Не обработана отмена | Проверка на `Неопределено` |
| Оповещение не вызывает продолжение | Имя, модуль, `Экспорт` | `ОписаниеОповещения`, сигнатура |
| После второго выбора список пуст | Накопились отборы | Менять свой элемент, а не добавлять новый |
| Пропали пользовательские условия | Вызван `Очистить()` | Менять только свой отбор |
| Не найден метод `ОбщегоНазначения…` | Это БСП, а не платформа | Наличие БСП или платформенный вариант |
| «Переменная не определена» у динамического реквизита | Его нет на этапе проверки | `ЭтотОбъект.ИмяРеквизита` |
| Старое окно — старый интерфейс | Открыт прежний экземпляр | Закрыть и открыть после `F7` |

## Три вида «объектов» в форме

| Запись | Что это | Что делаем |
| --- | --- | --- |
| `Объект.Покупатель` | Данные основного реквизита | Читаем, меняем значения |
| `Элементы.Покупатель` | Поле интерфейса | Видимость, доступность, оформление |
| `Объект.Товары` | Коллекция строк | Обходим, добавляем, удаляем строки |
| `Элементы.Товары` | Таблица интерфейса | Текущие данные (на клиенте) |
| `ДокументОбъект` после `РеквизитФормыВЗначение` | Прикладной объект на сервере | Методы модуля объекта |
| `Список` | Динамический список | Настройки и отборы, не перебор |

`Объект` формы документа — `ДанныеФормыСтруктура`, его таблица — `ДанныеФормыКоллекция` (и на клиенте, и на сервере). См. [ответ 1С о реквизитах и элементах](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Controls/Attributes_and_items_of_the_form__referring_to_them_from_the_module_of_the_form/?language=en).

## Шпаргалка по темам

| Тема | Главное правило |
| --- | --- |
| Клиент/сервер | Интерфейс — `&НаКлиенте`, база — сервер; предпочитаем `&НаСервереБезКонтекста`; один вызов на набор данных |
| Запись | Форма — удобство, модуль объекта — гарантия; `ТекущийОбъект` в серверных событиях записи; не пишем `Записать()` внутри `ПередЗаписью` |
| Открытие | Существующий — `Ключ`, новый — `ЗначенияЗаполнения`, свой параметр — читаем в `ПриСозданииНаСервере` |
| Выбор | `Закрыть(Значение)` + `ОписаниеОповещения` или `ОповеститьОВыборе` + `ОбработкаВыбора` |
| Списки | Динамический список читает порциями; отбор — свой элемент, без `Очистить()` |
| Вопросы | `Ждать ВопросАсинх(...)` или `ПоказатьВопрос` + продолжение; только на клиенте |

> [!question]- Вопросы для самопроверки
> 1. Почему `Элементы.Покупатель` нельзя использовать вместо `Объект.Покупатель` в проверке заполнения?
> 2. Почему одного имени `ПриОткрытии` у процедуры недостаточно?
> 3. Что вернёт `ТекущиеДанные` в пустой таблице?
> 4. Почему `Итог("Сумма")` не исправляет неверные суммы строк?
> 5. Где проверять количество, если документ записывает обмен?
> 6. Почему нельзя добавить строку сразу после `ОткрытьФорму()`?
> 7. Как снять свой отбор, сохранив остальные?
> 8. Чем загруженная таблица результатов отличается от динамического списка?
>
> > [!success]- Ответы
> > 1. Элемент — интерфейс, значение хранит реквизит.
> > 2. Событие назначается в свойствах формы.
> > 3. `Неопределено`.
> > 4. Метод складывает уже записанные числа.
> > 5. В модуле объекта.
> > 6. Выбор ещё не сделан — `ОткрытьФорму` не ждёт.
> > 7. `Использование = Ложь` у своего элемента отбора.
> > 8. Таблица хранит загруженный набор; список получает данные порциями и сам применяет отборы.

## Перед сдачей задачи

Проходим: успешный ввод, отмену, пустые значения, повторное открытие, программное изменение данных. Если затронута запись — серверные правила и повторное чтение. Если список — совместное действие отборов. Разбор ошибки — [[25. Отладка управляемой формы]], быстрый эксперимент — [[29. Учебная обработка и проверка примеров]].
