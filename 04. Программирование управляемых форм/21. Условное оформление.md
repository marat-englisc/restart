> [!abstract] Коротко
> **Условное оформление** меняет вид (цвет, шрифт, текст) при выполнении условия; данные не меняются. Правило = **оформление** + **условие** + **оформляемые поля**. У динамического списка — в «Настройке списка», у формы — свойство `УсловноеОформление` (редактор или код). В условии — путь к **данным**, в оформляемых полях — **элементы** формы.

## Непроведённые накладные в списке

`ФормаСпискаУчебная` → реквизит `Список` → **Настройка списка** → **Условное оформление** → **Добавить**:

1. **Оформление** — светло-жёлтый фон.
2. **Условие** — `Проведен` **Равно** `Ложь` (булево, не строка).
3. **Оформляемые поля** — `Номер`, `Дата` (не вся строка — иначе список станет «цветным пятном»).

Проверка: у непроведённой накладной выделены номер и дата; провели документ, обновили список — выделение исчезло. Пример — в [пособии 1С](https://1c-dn.com/library/tutorials/practical_developer_guide_lesson27_designer2/).

> [!tip] Цвет — не единственный сигнал
> Важные состояния дублируем колонкой или значком: цвет воспринимается по-разному.

## Нулевая цена в таблице документа

`ФормаДокумента` → корень «Форма» → свойство **УсловноеОформление**:

1. Оформление — светло-красный фон.
2. Условия (по **И**): `Объект.Товары.Цена` ≤ 0 и `Объект.Товары.Количество` > 0.
3. Оформляемое поле — элемент `ТоварыЦена`.

Условие табличной части применяется к **каждой строке** отдельно.

![[УФ-26-Условное-оформление.png]]

*Редактор «УсловноеОформление» (показан на общей форме подбора): колонки «Оформление», «Условие», «Оформляемые поля».*

## То же правило кодом

Вызываем один раз из `ПриСозданииНаСервере` (иначе правила будут множиться):

```1C
&НаСервере
Процедура ДобавитьОформлениеЦены()

	Правило = УсловноеОформление.Элементы.Добавить();
	Правило.Оформление.УстановитьЗначениеПараметра("ЦветФона", Новый Цвет(255, 235, 235));

	Условие = Правило.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
	Условие.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Объект.Товары.Цена");
	Условие.ВидСравнения = ВидСравненияКомпоновкиДанных.МеньшеИлиРавно;
	Условие.ПравоеЗначение = 0;

	Условие = Правило.Отбор.Элементы.Добавить(Тип("ЭлементОтбораКомпоновкиДанных"));
	Условие.ЛевоеЗначение = Новый ПолеКомпоновкиДанных("Объект.Товары.Количество");
	Условие.ВидСравнения = ВидСравненияКомпоновкиДанных.Больше;
	Условие.ПравоеЗначение = 0;

	Поле = Правило.Поля.Элементы.Добавить();
	Поле.Поле = Новый ПолеКомпоновкиДанных("ТоварыЦена");   // имя ЭЛЕМЕНТА формы

КонецПроцедуры
```

Если такое же правило уже настроено в редакторе — второе не нужно. `УсловноеОформление.Элементы.Очистить()` не вызываем: удалим чужие правила.

> [!info] Почему не красим строки кодом
> Правило условного оформления платформа применяет сама при выводе каждой строки. Не нужен код на каждое изменение данных, и приём работает в динамическом списке, строки которого форма не перебирает.

## Проверка

Три строки: (1 шт., 0 ₽), (1 шт., 100 ₽), (0 шт., 0 ₽) — выделена только цена первой. Меняем на 50 — выделение исчезло, обратно 0 — появилось.

| Симптом | Проверить |
| --- | --- |
| Красится вся форма/строка | Список оформляемых полей |
| Ничего не выделяется | Использование правила, пути данных, имя элемента |

Оформление **предупреждает**, но не запрещает запись нулевой цены — для запрета нужна проверка с `Отказ = Истина`.

> [!question]- Проверь себя
> 1. Что указывают в условии и что — в оформляемых полях?
> 2. Почему правило из кода добавляют в `ПриСозданииНаСервере`, а не в `ПриИзменении`?
> 3. Запретит ли оформление запись документа с нулевой ценой?
>
> > [!success]- Ответы
> > 1. Условие — путь к данным (`Объект.Товары.Цена`), оформляемые поля — элементы формы (`ТоварыЦена`).
> > 2. Иначе при каждом изменении добавится новое одинаковое правило.
> > 3. Нет, только изменит вид.
