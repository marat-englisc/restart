> [!abstract] Коротко
> Форма списка показывает много объектов; её основной реквизит — **ДинамическийСписок**: он читает данные из базы порциями, сам учитывает отбор и сортировку и даёт стандартные команды по **основной таблице**. В списке документов `Элементы.Список.ТекущаяСтрока` — **ссылка** на документ. Для расчётных результатов вместо него используют реквизит-таблицу значений.

![[УФ-14-Список-накладных.png]]

*Список расходных накладных в «1С:Купец».*

## Создаём учебную форму списка

1. `РасходнаяНакладная → Формы → Добавить` → **Форма списка**, имя `ФормаСпискаУчебная`.
2. Основной **не** назначаем — будем открывать по имени.
3. Поля: `Номер`, `Дата`, `Покупатель`, `ИтоговаяСумма`, `Проведен`.

## Реквизит `Список`

| Свойство | Значение |
| --- | --- |
| Тип | `ДинамическийСписок` (основной реквизит) |
| Основная таблица | `Документ.РасходнаяНакладная` |
| Произвольный запрос | Выключен (для первого примера) |

У таблицы — путь `Список`, у колонок — `Список.Номер` и т. д. Основная таблица нужна стандартным командам: открыть, создать, провести. Включая произвольный запрос, не удаляем ключевые поля. Отбор, сортировка и оформление списка работают на механизме СКД — см. [пособие 1С](https://1c-dn.com/library/tutorials/practical_developer_guide_lesson27_designer2/).

## Поле будущего фильтра

Реквизит формы `ПокупательОтбор` (тип как у `Покупатель` документа) → на форму **перед** таблицей, заголовок «Покупатель». Пока он ничего не фильтрует — связь сделаем в [[20. Программный отбор списка]].

## Открываем учебный список

В форме документа:

```1C
&НаКлиенте
Процедура ОткрытьУчебныйСписок(Команда)
	ОткрытьФорму("Документ.РасходнаяНакладная.Форма.ФормаСпискаУчебная");
КонецПроцедуры
```

`…ФормаСписка` открыла бы основную форму. См. [пояснение 1С об именах форм](https://its.1c.ru/db/content/metod8dev/src/developers/platform/qanda/form/form_open/i8104135.htm).

## Текущая накладная

```1C
&НаКлиенте
Процедура ПоказатьВыбраннуюНакладную(Команда)

	СсылкаНаНакладную = Элементы.Список.ТекущаяСтрока;
	Если СсылкаНаНакладную = Неопределено Тогда
		Сообщить("Выберите накладную");
		Возврат;
	КонецЕсли;
	Сообщить("Выбрана: " + СсылкаНаНакладную);

КонецПроцедуры
```

В списке с основной таблицей ключ строки — **ссылка** (в табличной части формы — идентификатор строки). Видимые поля строки — `Элементы.Список.ТекущиеДанные`, в них только колонки, которые список получает.

## Динамический список или таблица значений

| ДинамическийСписок | Реквизит «ТаблицаЗначений» |
| --- | --- |
| Платформа читает порциями | Код загружает весь набор |
| Просмотр объектов базы | Расчётные, промежуточные результаты |
| Стандартные команды есть | Команд редактирования нет |
| Отбор влияет на чтение | Строки — то, что загрузили |

Пример таблицы результата: реквизит `Результаты` (ТаблицаЗначений) с колонками `Номер` (Строка 30) и `Дата` (Дата и время), заранее выведенный на форму:

```1C
&НаКлиенте
Процедура ЗаполнитьРезультаты(Команда)
	ЗаполнитьРезультатыНаСервере();
КонецПроцедуры

&НаСервере
Процедура ЗаполнитьРезультатыНаСервере()
	Запрос = Новый Запрос(
	"ВЫБРАТЬ ПЕРВЫЕ 20
	|	Н.Номер КАК Номер,
	|	Н.Дата КАК Дата
	|ИЗ
	|	Документ.РасходнаяНакладная КАК Н
	|УПОРЯДОЧИТЬ ПО
	|	Дата УБЫВ");
	ЗначениеВРеквизитФормы(Запрос.Выполнить().Выгрузить(), "Результаты");
КонецПроцедуры
```

Колонки реквизита объявляем заранее — загрузка не создаёт колонки интерфейса.

> [!warning] Не обходим `Элементы.Список`
> Цикл по элементу списка не обработает «все накладные». Для массовой обработки — запрос на сервере с явными условиями.

> [!question]- Проверь себя
> 1. Что вернёт `Элементы.Список.ТекущаяСтрока` в списке документов?
> 2. Почему динамический список быстрее таблицы значений на большом объёме?
> 3. Зачем списку основная таблица?
>
> > [!success]- Ответы
> > 1. Ссылку на документ (или `Неопределено`).
> > 2. Он читает только видимую порцию данных.
> > 3. Для стандартных команд: открыть, создать, пометить, провести.
