Остальные объекты конфигурации

Коротко

Обзор объектов, которые встретятся в типовых решениях: планы видов характеристик (произвольные свойства), планы счетов и регистры бухгалтерии (проводки), планы видов расчёта и регистры расчёта (зарплата), бизнес-процессы и задачи (маршруты согласования), планы обмена, HTTP- и Web-сервисы. Выбираем объект по задаче, а не «на всякий случай».

Как ориентироваться в дереве

В дереве конфигурации есть объекты, которые мы пока не использовали. Не каждый из них нужен в небольшом приложении. Выбираем механизм по задаче, которую он решает.

Планы видов характеристик

План видов характеристик описывает набор характеристик и допустимые типы их значений. Например, для товаров нужны цвет, размер и материал, причём состав характеристик может расширяться.

В отличие от обычного реквизита справочника, новый вид характеристики можно описать как данные. Сам план описывает виды, а значения конкретных товаров нужно хранить отдельно, например в регистре сведений.

Если у всех товаров всегда только один фиксированный признак Цвет, обычный реквизит может быть проще.

Планы счетов и регистры бухгалтерии

План счетов описывает счета учёта. Регистр бухгалтерии хранит связанные с ними учётные записи и поддерживает необходимые механизмы бухгалтерского учёта.

Это нужно для задач с проводками, счетами, субконто и другими правилами бухгалтерии. Для простого количества товара на складе достаточно регистра накопления. Добавлять бухгалтерский регистр только потому, что в учёте есть деньги, не обязательно.

Планы видов расчёта и регистры расчёта

План видов расчёта описывает виды расчёта и их зависимости. Регистр расчёта хранит расчётные записи и поддерживает механизмы периода действия, базы и перерасчётов.

Типичный пример - начисления зарплаты, где результат зависит от периода, других начислений и вытеснения одного вида расчёта другим.

Для простого умножения количества на цену эти механизмы не нужны.

Бизнес-процессы и задачи

Бизнес-процесс описывает маршрут работы. Задачи содержат конкретные действия для исполнителей.

Например: менеджер создал заявку -> руководитель согласовал -> кладовщик получил задачу отгрузить товар. Маршрут может содержать условия и параллельные действия.

Если нам нужен только статус документа, сначала достаточно реквизита с перечислением. Процесс нужен, когда важно организовать сам маршрут и выполнение задач.

Планы обмена

План обмена описывает участников обмена и позволяет регистрировать изменения данных для передачи между узлами. Правила передачи, сопоставления и разрешения конфликтов требуют отдельной реализации или готового механизма конфигурации.

Простая выгрузка таблицы в файл ещё не является полноценной синхронизацией: нужно также решить, как узнавать изменённые объекты и что делать с удалениями.

Внешние источники и сервисы

Внешние источники данных позволяют описывать доступ к внешним данным. HTTP-сервисы и Web-сервисы используются для взаимодействия приложения с другими системами.

У интеграции отдельно продумывают формат данных, проверку входных значений, права, повторную обработку и поведение при ошибках связи. Базовую работу с JSON разберём в 31. Файлы, JSON и временное хранилище.

Как выбирать объект

ЗадачаС чего начать
Список товаров и покупателейСправочник
Зафиксировать продажуДокумент
Учесть изменение количестваРегистр накопления
Хранить историю ценыРегистр сведений
Выполнить загрузку или проверкуОбработка
Вывести документы разных видов вместеЖурнал документов
Включить необязательную возможностьФункциональная опция

Подробное освоение бухгалтерского учёта, расчётов и интеграций требует отдельных примеров. Здесь важно понимать назначение объектов и не подменять ими уже подходящий простой механизм.

Проверь себя

  1. Нужно хранить цвет, размер, материал — и список свойств будут пополнять пользователи. Какой объект?

  2. Нужен ли регистр бухгалтерии для учёта количества товара на складе?

  3. Документ проходит согласование: менеджер → руководитель → склад. Какой механизм?

Ответы
  1. План видов характеристик + регистр сведений для значений.
  2. Нет, достаточно регистра накопления остатков.
  3. Бизнес-процесс с задачами исполнителей.
