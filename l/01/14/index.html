Документы

Коротко

Документ фиксирует событие или хозяйственную операцию: заказ, продажу, поступление, приём на работу. У документа есть номер, дата и признак «Проведён». Проведение — момент, когда документ влияет на учёт: формирует движения в регистрах. Документ можно связать с другими через ввод на основании.

Что это такое

Документы хранят информацию о совершённых операциях и событиях: приходные и расходные накладные, счета, платёжные поручения, приказы.

Пример документа «ЗаказКлиента»: у каждого — номер, дата со временем и сумма.

СправочникДокумент
Что описываетОбъект учёта: что/кто (товар, клиент)Событие: что произошло (продали товар клиенту)
Ключевые реквизитыКод, НаименованиеНомер, Дата, Проведён
Влияет на учётНетДа, при проведении — через регистры

Связь параметров выбора

Договор должен выбираться только из договоров выбранного покупателя. Открываем свойства реквизита Договор → вкладка «Представление» → «Связи параметров выбора»:

Свойство «Связи параметров выбора» реквизита Договор: уже настроено Отбор.Владелец(Покупатель).

В окне связей переносим Покупатель вправо и выбираем параметр Отбор.Владелец:

Окно связей параметров выбора: слева реквизиты документа.

Связь Отбор.Владелец = Покупатель; «Режим изменения: Очищать» — при смене покупателя договор очистится.

Теперь форма выбора договора открывается с отбором по владельцу. Подчинённость договоров контрагенту настраивается в самом справочнике Договоры (08. Справочники), а связь параметров выбора лишь использует её в поле.

Связи и параметры выбора
  • Связи параметров выбора — отбор берётся из другого реквизита этого же объекта (Отбор.Владелец ← Покупатель).
  • Параметры выбора — отбор по фиксированному значению (Отбор.ВидНоменклатуры = Товар), см. ниже.

Оба механизма облегчают ввод, но не гарантируют правильность данных при программной записи: проверку дублируем в модуле объекта (24. Программная работа с документами).

Проведение

Проведение отвечает на вопрос «влияет ли документ на учёт». Учётные данные хранятся в регистрах: при проведении документ записывает в них движения, при отмене проведения — удаляет их.

Признак «Проведен»: первые два документа учтены, третий — нет.

  • Проводимые: расходная накладная (уменьшает остаток, увеличивает продажи), поступление товаров.
  • Непроводимые: коммерческое предложение — клиент может и отказаться, на учёт оно не влияет. Для таких документов на вкладке «Движения» ставим Проведение: Запретить.

Как документ формирует движения — в 17. Регистры накоплений.

Состояния документа в списке

СостояниеЗначок
Записан, не проведён
Проведён (зелёная галочка)
Помечен на удаление
Пометка удаления отменяет проведение

Документ не может быть одновременно проведённым и помеченным на удаление. При пометке проведение отменяется (движения удаляются); при снятии пометки документ остаётся непроведённым — его нужно провести заново.

Ввод на основании

Ввод на основании создаёт новый документ, заполненный данными другого объекта: по заказу клиента — расходную накладную.

Из заказа в накладную переносятся контрагент, договор, сумма и товары.

Настраиваем в документе, который будем создавать (РасходнаяНакладная) → вкладка «Ввод на основании»:

Вкладка «Ввод на основании»: сверху — на основании чего вводится этот документ, снизу — для чего он сам является основанием.

Карандашом у списка «Вводится на основании» выбираем ЗаказКлиента:

Выбор объекта-основания.

Нажимаем «Конструктор ввода на основании»: слева вверху — основание, справа — его реквизиты, внизу — соответствие полей нового документа:

Пустой конструктор: поля новой накладной ещё не связаны с заказом.

«Заполнить выражения» проставит соответствия по совпадающим именам — остаётся проверить их:

Выражения заполнены: ДанныеЗаполнения.Покупатель, строки — из ТекСтрокаТовары, Основание = ДанныеЗаполнения.Ссылка.

После ОК в модуле объекта появится обработчик ОбработкаЗаполнения:

Разбор:

  • ДанныеЗаполнения — то, на основании чего заполняем документ. Здесь — ссылка на заказ клиента.
  • ТипЗнч(...) = Тип(...) — проверяем, что основание именно заказ: документ может вводиться на основании разных объектов.
  • Обращения через точку (ДанныеЗаполнения.Договор) читают реквизиты заказа по ссылке.
  • Товары.Добавить() — добавляем строку в табличную часть нового документа.
Ручные правки внутри блока конструктора

Код между //{{__КОНСТРУКТОР… и //}}__КОНСТРУКТОР… будет перезаписан при повторном запуске конструктора. Свою логику пишем вне этого блока.

В Предприятии в форме заказа появится команда «Создать на основании → Расходная накладная».

Проверь себя

  1. Чем документ принципиально отличается от справочника?

  2. Что физически происходит при проведении документа?

  3. Документ проведён, его пометили на удаление, потом сняли пометку. Он проведён?

  4. Чем связи параметров выбора отличаются от параметров выбора?

Ответы
  1. Документ описывает событие во времени (есть дата) и может влиять на учёт, формируя движения регистров.
  2. Выполняется ОбработкаПроведения: в регистры записываются движения, Проведен = Истина.
  3. Нет: пометка отменила проведение, документ нужно провести заново.
  4. Связи берут значение отбора из другого реквизита объекта, параметры выбора — фиксированное значение.
