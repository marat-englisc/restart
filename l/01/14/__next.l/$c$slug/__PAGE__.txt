<div class="callout-title">Коротко</div>
<div class="callout-body"><p><strong>Документ</strong> фиксирует событие или хозяйственную операцию: заказ, продажу, поступление, приём на работу. У документа есть <strong>номер, дата и признак «Проведён»</strong>. <strong>Проведение</strong> — момент, когда документ влияет на учёт: формирует <strong>движения</strong> в регистрах. Документ можно связать с другими через <strong>ввод на основании</strong>.</p></div>
</div>
<h2 id="что-это-такое">Что это такое</h2>
<p><strong>Документы</strong> хранят информацию о совершённых операциях и событиях: приходные и расходные накладные, счета, платёжные поручения, приказы.</p>
<p><img src="/restart/vault/%D0%9A%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%BA%D0%B8/Pasted%20image%2020260910203336.png" alt="Pasted image 20260910203336.png" loading="lazy" decoding="async"></p>
<p><em>Пример документа «ЗаказКлиента»: у каждого — номер, дата со временем и сумма.</em></p>

























<div class="table-wrap"><table><thead><tr><th></th><th>Справочник</th><th>Документ</th></tr></thead><tbody><tr><td>Что описывает</td><td>Объект учёта: <strong>что/кто</strong> (товар, клиент)</td><td>Событие: <strong>что произошло</strong> (продали товар клиенту)</td></tr><tr><td>Ключевые реквизиты</td><td>Код, Наименование</td><td>Номер, <strong>Дата</strong>, Проведён</td></tr><tr><td>Влияет на учёт</td><td>Нет</td><td>Да, при проведении — через регистры</td></tr></tbody></table></div>

<h3 id="связь-параметров-выбора">Связь параметров выбора</h3>
<p>Договор должен выбираться <strong>только из договоров выбранного покупателя</strong>. Открываем свойства реквизита <code>Договор</code> → вкладка <strong>«Представление»</strong> → <strong>«Связи параметров выбора»</strong>:</p>
<p><img src="/restart/vault/%D0%9A%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%BA%D0%B8/Pasted%20image%2020260911110533.png" alt="Pasted image 20260911110533.png" loading="lazy" decoding="async"></p>
<p><em>Свойство «Связи параметров выбора» реквизита <code>Договор</code>: уже настроено <code>Отбор.Владелец(Покупатель)</code>.</em></p>
<p>В окне связей переносим <code>Покупатель</code> вправо и выбираем параметр <code>Отбор.Владелец</code>:</p>
<p><img src="/restart/vault/%D0%9A%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%BA%D0%B8/Pasted%20image%2020260911111151.png" alt="Pasted image 20260911111151.png" loading="lazy" decoding="async"></p>

<p><em>Связь <code>Отбор.Владелец = Покупатель</code>; «Режим изменения: Очищать» — при смене покупателя договор очистится.</em></p>
<p>Теперь форма выбора договора открывается с отбором по владельцу. Подчинённость договоров контрагенту настраивается в самом справочнике <code>Договоры</code> (<a href="/restart/l/01/08/" data-internal="true">08. Справочники</a>), а связь параметров выбора лишь использует её в поле.</p>
<div class="callout callout-info" data-callout="info">
<div class="callout-title">Связи и параметры выбора</div>
<div class="callout-body"><ul>
<li><strong>Связи параметров выбора</strong> — отбор берётся из <strong>другого реквизита</strong> этого же объекта (<code>Отбор.Владелец ← Покупатель</code>).</li>
<li><strong>Параметры выбора</strong> — отбор по <strong>фиксированному значению</strong> (<code>Отбор.ВидНоменклатуры = Товар</code>), см. ниже.</li>
</ul><p>Оба механизма облегчают ввод, но не гарантируют правильность данных при программной записи: проверку дублируем в модуле объекта (<a href="/restart/l/02/24/" data-internal="true">24. Программная работа с документами</a>).</p></div>
</div>

<h2 id="проведение">Проведение</h2>
<p><strong>Проведение</strong> отвечает на вопрос «влияет ли документ на учёт». Учётные данные хранятся в <strong>регистрах</strong>: при проведении документ записывает в них <strong>движения</strong>, при отмене проведения — удаляет их.</p>
<p><img src="/restart/vault/%D0%9A%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%BA%D0%B8/Pasted%20image%2020260911120708.png" alt="Pasted image 20260911120708.png" loading="lazy" decoding="async"></p>
<p><em>Признак «Проведен»: первые два документа учтены, третий — нет.</em></p>
<ul>
<li>Проводимые: расходная накладная (уменьшает остаток, увеличивает продажи), поступление товаров.</li>
<li>Непроводимые: коммерческое предложение — клиент может и отказаться, на учёт оно не влияет. Для таких документов на вкладке «Движения» ставим <strong>Проведение: Запретить</strong>.</li>
</ul>
<p>Как документ формирует движения — в <a href="/restart/l/01/17/" data-internal="true">17. Регистры накоплений</a>.</p>

<p>Чем документ принципиально отличается от справочника?</p>

<li>Выполняется <code>ОбработкаПроведения</code>: в регистры записываются движения, <code>Проведен = Истина</code>.</li>
<li>Нет: пометка отменила проведение, документ нужно провести заново.</li>
<li>Связи берут значение отбора из другого реквизита объекта, параметры выбора — фиксированное значение.</li>
