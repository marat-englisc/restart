Регистр остатков на практике

Коротко

Строим складской учёт: регистр накопления остатков ТоварыНаСкладах (измерения Номенклатура, Склад; ресурс Количество). Приходная накладная пишет приход, расходная — расход. Остаток на дату читаем виртуальной таблицей Остатки, движение за период — ОстаткиИОбороты. Это основа для контроля остатков в следующей теме.

Подготовка объектов

ОбъектЧто добавить
Справочник СкладыЕсли нет — создать (есть в учебной базе, тема 22)
ПриходнаяНакладнаяРеквизит Склад, табличная часть Товары (Товар, Количество, Цена, Сумма)
РасходнаяНакладнаяРеквизит Склад (значение заполнения — ОсновнойСклад, проверка заполнения)
Регистр накопления ТоварыНаСкладахВид Остатки; измерения Номенклатура (СправочникСсылка.Номенклатура), Склад (СправочникСсылка.Склады); ресурс Количество (Число 15,3)

Регистраторы регистра — обе накладные. В подсистему «Торговый учёт» включаем регистр (для просмотра) и будущий отчёт.

В открытой учебной базе ТоварыНаСкладах имеет вид «Остатки». Для оборотного регистра виртуальная таблица Остатки недоступна.

Вкладка «Данные»: два измерения (Номенклатура, Склад) и ресурс Количество. Типы измерений задайте по таблице выше.

Свойства ресурса Количество: числовой тип с точностью 3 знака после запятой. Для движений прихода и расхода передаём положительное количество; направление задаёт вид движения.

Вкладка «Регистраторы»: отмечены приходная и расходная накладные. ЗаказКлиента остатки не изменяет и здесь не отмечен.

Почему количество, а не сумма

Для простого складского учёта храним только количество. Учёт себестоимости (сумма в регистре, партии, FIFO) — отдельная, заметно более сложная задача.

Модуль объекта ПриходнаяНакладная:

ДобавитьПриход() = Добавить() + ВидДвижения = ВидДвиженияНакопления.Приход.

Проведение расхода

В ОбработкаПроведения расходной накладной к уже существующим движениям продаж добавляем:

Услуги в складской регистр не пишем — их нет на складе.

Одинаковые товары в нескольких строках

Если товар встречается в двух строках, будет два движения — это нормально, регистр их сложит. Но для контроля остатков удобнее сначала свернуть строки по товару (тема 02).

Остатки на дату

Серверная функция (общий модуль СкладСервер, флаг «Сервер»):

  • Отбор по складу — в параметрах виртуальной таблицы, а не в ГДЕ: так платформа считает только нужное.
  • Новый Граница(…, ВидГраницы.Включая) включает движения последней секунды дня.
  • КоличествоОстаток — ресурс + суффикс Остаток.

Ведомость за период

Параметры ОстаткиИОбороты: начало, конец, периодичность, метод дополнения, условие. Проверка: Начало + Приход − Расход = Конец. Отчёт на СКД по этому запросу собирается по шагам темы 20 раздела 03: ресурсы — суммы всех четырёх колонок.

Проверка сценария

ДокументСкладТоварКол-воОстаток после
Приход 01.10ОсновнойЧайник1010
Расход 05.10ОсновнойЧайник37
Расход 06.10ВторойЧайник1−1 на «Второй»

Последняя строка — ловушка: регистр разрешил отрицательный остаток. Платформа не контролирует наличие товара — это делаем в 02. Контроль остатков и блокировки.

Проверь себя

  1. Почему складской регистр — «Остатки», а продажи — «Обороты»?

  2. Зачем передавать склад в параметры Остатки(...), а не в ГДЕ?

  3. Что будет, если провести расход на склад, где товара нет?

Ответы
  1. Для склада важен остаток на дату; для продаж — только обороты за период.
  2. Платформа ограничит расчёт итогов нужным складом — быстрее и точнее.
  3. Остаток уйдёт в минус: регистр сам этого не запрещает.
