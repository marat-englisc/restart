Итоговый проект и собеседование

Коротко

Финальная проверка курса: итоговый проект «Мини-склад» объединяет все разделы — от справочников до HTTP-сервиса — и годится в портфолио. Ниже — техническое задание, критерии готовности и 50 вопросов с короткими ответами, которые задают на собеседовании junior-разработчику 1С.

Готово, если: нельзя провести расход больше остатка (даже из двух сеансов одновременно); повторное проведение не дублирует движения; ведомость сходится (начало + приход − расход = конец); кладовщик не видит цен; сервис отдаёт корректный JSON и код 404 для неизвестного товара; выгрузка .dt восстанавливается в пустую базу.

Уточните границы контроля: алгоритм темы 02 проверяет оперативный расход по текущим итогам. Для требования «минус запрещён всегда» отдельно реализуйте и проверьте изменение дат, неоперативное проведение, отмену прихода и перемещение между складами. Скрыть цены в форме кладовщика недостаточно — проверьте доступ к ним также через отчёты и программное чтение.

Сохраните фактические результаты и скриншоты своего проекта. Иллюстрации редакторов из конспекта показывают подготовку, а не доказывают прохождение этих сценариев. В учебной версии недоступна проверка двух одновременных сеансов; такой пункт отмечаем как «не проверен на этом стенде».

Для портфолио

Выгрузите конфигурацию в файлы (или ведите проект в EDT) и положите в Git-репозиторий с README: что умеет программа, скриншоты, как развернуть. Это сильнее любого сертификата.

Вопросы к собеседованию

Платформа и конфигурирование
  1. Чем конфигурация отличается от информационной базы? — Конфигурация — описание программы; ИБ — конфигурация + данные.
  2. Основная конфигурация и конфигурация БД? — Первую редактирует разработчик, вторую использует пользователь; переносим изменения F7.
  3. Файловый и клиент-серверный вариант? — Файл 1Cv8.1CD или СУБД + сервер 1С; код делится на клиент/сервер в обоих.
  4. Справочник или документ? — Справочник — что/кто (список объектов), документ — событие во времени, может влиять на учёт.
  5. Перечисление или справочник? — Перечисление — фиксированный набор, задаёт разработчик; справочник пополняют пользователи.
  6. Регистр накопления остатков vs оборотов? — Остатки — есть остаток на дату и приход/расход; обороты — только изменения за период.
  7. Регистр сведений vs накопления? — Сведения хранят значения (цена), накопления — складываемые изменения (количество).
  8. Периодический независимый регистр сведений — ключ записи? — Период + измерения.
  9. Что такое проведение? — Запись документа с формированием движений в регистрах (ОбработкаПроведения).
  10. Что делает пометка удаления? — Ставит признак; удаление помеченных удаляет объект только при отсутствии ссылок.
  11. Владелец справочника vs ссылочный реквизит? — Владелец делает элемент подчинённым (договор без контрагента не существует), обычный реквизит — просто связь.
  12. Зачем подсистемы? — Разделы интерфейса и логическая группировка объектов.
  13. Функциональная опция? — Включает/выключает функциональность по значению (константы), без изменения конфигурации.
  14. Что такое расширение и зачем оно? — Отдельный слой доработок; типовая остаётся на поддержке.
  15. .cf, .cfe, .dt, .epf? — Конфигурация; расширение; выгрузка ИБ с данными; внешняя обработка.
Встроенный язык

16. Процедура vs функция? — Функция возвращает значение через Возврат. 17. Как передаются параметры? — По ссылке; Знач — по значению (для коллекций копии не создаёт). 18. Неопределено, NULL, пустая ссылка? — Нет значения в языке; нет значения в результате запроса; значение ссылочного типа без объекта. 19. Структура vs Соответствие? — Ключ структуры — строка-имя, соответствия — любое значение. 20. Где работает ТаблицаЗначений? — На сервере (и толстом клиенте); в управляемой форме — ДанныеФормыКоллекция. 21. Менеджер, ссылка, объект? — Менеджер — операции с видом; ссылка — указатель (чтение); объект — изменение и запись. 22. Отказ vs Возврат в ПередЗаписью? — Отказ = Истина отменяет запись; Возврат только выходит из процедуры. 23. Почему нельзя Записать() в ПередЗаписью? — Рекурсия. 24. Попытка-Исключение: что нельзя? — Пустой блок Исключение; заменять ею обычные проверки. 25. Транзакция — шаблон? — НачатьТранзакцию(); Попытка … ЗафиксироватьТранзакцию(); Исключение ОтменитьТранзакцию(); ВызватьИсключение; КонецПопытки;. 26. Подписка на событие? — Общий обработчик события для нескольких объектов из общего модуля. 27. Фоновое vs регламентное задание? — Фоновое — запуск метода отдельно сейчас; регламентное — по расписанию. 28. Асинх/Ждать — что делает? — Позволяет ждать результата асинхронной операции на клиенте без блокировки интерфейса; не параллелит вычисления.

Запросы и СКД

29. ГДЕ vs ИМЕЮЩИЕ? — Отбор строк до группировки / групп после. 30. Левое соединение — когда? — Нужны все строки левой таблицы, даже без пары справа (будет NULL). 31. Почему сумма выросла после соединения? — Справа несколько совпадений — строки размножились. 32. ЕСТЬNULL? — Заменяет NULL значением. 33. ОБЪЕДИНИТЬ vs ОБЪЕДИНИТЬ ВСЕ? — Первое удаляет дубли. 34. Временная таблица и пакет? — ПОМЕСТИТЬ + ;; промежуточный результат для следующих запросов. 35. Виртуальные таблицы регистра накопления? — Обороты, Остатки, ОстаткиИОбороты; отборы — в параметры. 36. Срез последних? — Последняя запись регистра сведений не позже даты по каждому сочетанию измерений. 37. Почему запрос в цикле — плохо? — N обращений к базе; данные нужно получить одним запросом. 38. РАЗРЕШЕННЫЕ? — Отбрасывает записи, недоступные по RLS; прав не даёт. 39. Схема СКД vs настройки? — Откуда данные и возможности / как вывести. 40. Ресурс СКД? — Поле с формулой итога по группировкам.

Управляемые формы

41. Объект vs Элементы? — Данные формы / элементы интерфейса. 42. Директивы формы? — &НаКлиенте, &НаСервере, &НаСервереБезКонтекста, &НаКлиентеНаСервереБезКонтекста. 43. Почему &НаСервереБезКонтекста предпочтительнее? — Не передаются данные формы. 44. ПриСозданииНаСервере vs ПриОткрытии? — Сервер, подготовка данных / клиент, интерфейсные действия. 45. Как вызвать метод модуля объекта из формы? — РеквизитФормыВЗначение → метод → ЗначениеВРеквизитФормы. 46. Как открыть существующий документ / новый с заполнением? — Параметр Ключ / ЗначенияЗаполнения. 47. Как получить результат из открытой формы? — Закрыть(Значение) + ОписаниеОповещения (или ОповеститьОВыборе). 48. Динамический список? — Основной реквизит формы списка, читает данные порциями, отборы через компоновку. 49. Вызовется ли ПриИзменении при присваивании в коде? — Нет, только при интерактивном вводе. 50. Где проверять обязательные правила? — В модуле объекта (или подписке); форма — только подсказка.

Ситуационные вопросы
  • Документ проводится 30 секунд. С чего начнёте? — Замер производительности: запросы в цикле, тяжёлые обращения через точку, отборы виртуальных таблиц, блокировки.
  • Пользователь видит «Недостаточно прав», администратор — нет. — Роли пользователя, RLS, запросы без РАЗРЕШЕННЫЕ; воспроизвести под этим пользователем.
  • Остаток ушёл в минус. — Нет контроля остатков или он без блокировки; проверить проведение и одновременные сеансы.
  • Нужно доработать типовую. — Расширение; механизмы БСП; разметка изменений; проверка после обновления.

Что изучать дальше

  • Типовая конфигурация «1С:Управление торговлей» или «1С:Бухгалтерия»: читать код проведения и печати, искать механизмы БСП.
  • Сертификация «1С:Профессионал» по платформе — хорошая проверка базы.
  • Учёт: бухгалтерский (регистр бухгалтерии, план счетов) и расчётный (зарплата) — если интересна соответствующая специализация (29. Остальные объекты).
