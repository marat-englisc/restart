<div class="callout-title">Коротко</div>
<div class="callout-body"><p>Обращение к внешнему REST API: <code>HTTPСоединение</code> (сервер, порт, таймаут, SSL) + <code>HTTPЗапрос</code> (адрес ресурса, заголовки, тело) → <code>Получить()</code> / <code>ОтправитьДляОбработки()</code> / <code>ВызватьHTTPМетод()</code> → <code>HTTPОтвет</code> (<code>КодСостояния</code>, тело). Тело JSON разбираем <code>ПрочитатьJSON</code>. Выполняем <strong>на сервере</strong>, с таймаутом и обработкой ошибок, без секретов в коде и <strong>вне транзакции</strong>.</p></div>
</div>

<h2 id="get-запрос-и-разбор-json">GET-запрос и разбор JSON</h2>
<p>Общий модуль <code>ИнтеграцияСервер</code> (флаг «Сервер»):</p>
<p><img src="/restart/vault/%D0%9A%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%BA%D0%B8/05.%20%D0%9F%D1%80%D0%BE%D1%84%D0%B5%D1%81%D1%81%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D0%B0%D1%8F%20%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%BA%D0%B0/06-%D0%A1%D0%B2%D0%BE%D0%B9%D1%81%D1%82%D0%B2%D0%B0-%D1%81%D0%B5%D1%80%D0%B2%D0%B5%D1%80%D0%BD%D0%BE%D0%B3%D0%BE-%D0%BC%D0%BE%D0%B4%D1%83%D0%BB%D1%8F.png" alt="06-Свойства-серверного-модуля.png" loading="lazy" decoding="async"></p>
<p><em>Палитра существующего серверного модуля <code>ПроверкиОбъектов</code>: «Сервер» включён, «Клиент» и «Вызов сервера» выключены. Это образец расположения свойств, а не готовый модуль интеграции. Для <code>ИнтеграцияСервер</code> создайте отдельный модуль с флагом «Сервер»; флаг «Внешнее соединение» из показанного модуля копировать для HTTP-запроса не нужно.</em></p>
<p>Адрес <code>api.example.ru</code> и <code>/v1/rates</code> — <strong>условный контракт</strong>, не готовый сервис курсов. Перед запуском подставьте адрес реального API и реализуйте <code>ТокенAPI()</code> по правилам своего решения; в учебном стенде удобно использовать локальный сервис с заранее известным JSON.</p>

<p>После чтения проверьте структуру ответа: корнем JSON может быть не объект, а массив, строка или <code>null</code>. Код <code>200</code> не гарантирует ни корректный JSON, ни ожидаемые поля. Для POST и остальных методов также нужны обработка сетевой ошибки и проверка <code>КодСостояния</code>, как в GET-примере.</p>

<h2 id="правила-надёжной-интеграции">Правила надёжной интеграции</h2>

































<div class="table-wrap"><table><thead><tr><th>Правило</th><th>Почему</th></tr></thead><tbody><tr><td>HTTP-вызов <strong>вне транзакции</strong> (не в <code>ПередЗаписью</code>/<code>ОбработкаПроведения</code>)</td><td>Транзакция держит блокировки, пока ждём ответ; откат транзакции не отменит уже отправленный запрос</td></tr><tr><td>Регламентное или фоновое задание для регулярного обмена</td><td>Пользователь не ждёт сеть (<a href="/restart/l/02/32/" data-internal="true">32. Фоновые задания</a>)</td></tr><tr><td>Токены и пароли — не в коде</td><td>Константа с ограниченными правами или безопасное хранилище БСП (<code>ОбщегоНазначения.ПрочитатьДанныеИзБезопасногоХранилища</code>)</td></tr><tr><td>Идемпотентность</td><td>Повторная отправка не должна создавать дубль: передаём наш идентификатор, проверяем «уже отправлено»</td></tr><tr><td>Журнал регистрации</td><td>Код ответа и кратко тело ошибки — для разбора без отладчика</td></tr><tr><td>Проверка входных данных</td><td>Корректный JSON может содержать неожиданные значения (<a href="/restart/l/02/31/" data-internal="true">31. JSON</a>)</td></tr></tbody></table></div>
