<div class="callout-body"><p><strong>HTTP-сервис</strong> — объект конфигурации, который делает базу 1С REST-сервером: <strong>корневой URL</strong> → <strong>шаблоны URL</strong> (<code>/stock/{code}</code>) → <strong>методы</strong> (GET, POST…) → функция-обработчик <code>(Запрос) → HTTPСервисОтвет</code>. Код выполняется на сервере с правами пользователя, под которым идёт подключение.</p></div>

<p>Это <strong>каркас POST</strong>, а не готовая загрузка заказов: он возвращает <code>400</code> для некорректного JSON и <code>501</code> для разбираемого JSON. Перед заменой последнего <code>Возврат</code> проверьте тип корневого значения, обязательные поля, права и повторную отправку одного заказа. Обработчик должен возвращать <code>HTTPСервисОтвет</code> на каждом пути выполнения.</p>
<p>Код ответа — часть контракта: <code>200</code> — ок, <code>201</code> — создано, <code>400</code> — плохой запрос, <code>401/403</code> — нет доступа, <code>404</code> — не найдено, <code>422</code> — данные не прошли проверку, <code>500</code> — ошибка сервера.</p>
<h2 id="публикация-и-вызов">Публикация и вызов</h2>
<ol>
<li>Нужен веб-сервер (IIS или Apache) и установленный модуль расширения веб-сервера 1С.</li>
<li>Конфигуратор (запущенный от администратора ОС) → <strong>Администрирование → Публикация на веб-сервере</strong> → имя публикации <code>kupets</code>, флажок <strong>«Публиковать HTTP-сервисы»</strong>.</li>
<li>Вызов:</li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="mono"><code data-language="bash" data-theme="mono" style="display: grid;"><span data-line=""><span style="color:var(--shiki-token-function)">curl</span><span style="color:var(--shiki-token-string)"> -u</span><span style="color:var(--shiki-token-string-expression)"> "Пользователь:Пароль"</span><span style="color:var(--shiki-token-string)"> http://localhost/kupets/hs/stock/balance/000000001</span></span></code></pre></figure>
<p>Ответ: <code>{"code":"000000001","name":"Чайник \"Победа\"","balance":7}</code>.</p>
<div class="callout callout-warning" data-callout="warning">
<div class="callout-title">Безопасность</div>
<div class="callout-body"><ul>
<li>Подключение идёт под <strong>пользователем 1С</strong>, определённым настройками аутентификации публикации. Заголовок <code>Bearer</code> сам по себе не реализует вход по произвольному токену: такой способ требует отдельного механизма проверки. Для интеграции нужен пользователь с правами только на нужные объекты.</li>
<li>Публикуем по HTTPS.</li>
<li>Не доверяем входным данным: проверяем типы, длины, существование ссылок.</li>
<li>Не возвращаем подробный текст исключения наружу — пишем его в журнал регистрации, клиенту — краткое сообщение.</li>
</ul></div>
