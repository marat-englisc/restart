<h2 id="заполненность--правильность">Заполненность ≠ правильность</h2>
<p>Свойство реквизита <strong>«Проверка заполнения: Выдавать ошибку»</strong> проверяет только «не пусто». Отрицательное количество заполнено, но недопустимо. Красное подчёркивание поля — подсказка интерфейса. Программный <code>Записать()</code> не обязан выполнять проверки формы. Подробнее — <a href="https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1808293" target="_blank" rel="noopener noreferrer">руководство 1С, 5.6.12</a>.</p>

<div class="callout-title">Внимание</div>
<div class="callout-body"><p><code>Отказ</code>, а не <code>Возврат</code>
<code>Отказ = Истина</code> останавливает запись; один <code>Возврат</code> — нет. <code>Отказ = Ложь</code> не пишем: его могла выставить другая проверка. Существующий <code>ПередЗаписью</code> дополняем, а не создаём второй.</p></div>

<div class="callout-title">Альтернатива —</div>
<div class="callout-body"><p><code>ОбработкаПроверкиЗаполнения</code>
Это событие модуля объекта вызывается при интерактивной записи и при явном <code>ПроверитьЗаполнение()</code>; в нём удобно добавлять свои проверки к стандартной «Проверке заполнения» реквизитов. Но при программном <code>Записать()</code> оно само не вызывается — для правил, которые должны действовать <strong>всегда</strong>, надёжнее <code>ПередЗаписью</code>.</p></div>

<li>Пустой покупатель → «Проверить» → сообщение у поля покупателя.</li>
<li>Строка без товара → сообщение у колонки товара.</li>
<li>Количество 0 → сообщение о количестве.</li>
<li>Отрицательная цена → сообщение о цене (если тип её допускает).</li>
<li>Некорректная накладная, кнопка <strong>«Записать»</strong> → серверная проверка запрещает запись даже без «Проверить».</li>
</ol>
