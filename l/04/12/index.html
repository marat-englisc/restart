Проверка заполнения и сообщения

Коротко

Проверку делаем на двух уровнях: в форме — чтобы подсказать пользователю до записи (сообщение привязано к полю), в модуле объекта — обязательно, при любой записи (ПередЗаписью или ОбработкаПроверкиЗаполнения, Отказ = Истина). Сообщение к полю: СообщениеПользователю с Поле и ПутьКДанным/УстановитьДанные().

Правила примера: покупатель обязателен; в каждой строке товаров — товар, количество > 0, цена ≥ 0. Пустую табличную часть Товары не запрещаем — в накладной есть услуги.

Заполненность ≠ правильность

Свойство реквизита «Проверка заполнения: Выдавать ошибку» проверяет только «не пусто». Отрицательное количество заполнено, но недопустимо. Красное подчёркивание поля — подсказка интерфейса. Программный Записать() не обязан выполнять проверки формы. Подробнее — руководство 1С, 5.6.12.

Сообщение, привязанное к полю (форма)

  • Поле — путь к данным, а не имя элемента. Без второго префикса Объект.
  • Индекс в Товары[0] начинается с 0, номер строки для пользователя — с 1. См. статью 1С о сообщениях.

Внимание

Отказ, а не Возврат Отказ = Истина останавливает запись; один Возврат — нет. Отказ = Ложь не пишем: его могла выставить другая проверка. Существующий ПередЗаписью дополняем, а не создаём второй.

Альтернатива —

ОбработкаПроверкиЗаполнения Это событие модуля объекта вызывается при интерактивной записи и при явном ПроверитьЗаполнение(); в нём удобно добавлять свои проверки к стандартной «Проверке заполнения» реквизитов. Но при программном Записать() оно само не вызывается — для правил, которые должны действовать всегда, надёжнее ПередЗаписью.

Проверяем по очереди

  1. Пустой покупатель → «Проверить» → сообщение у поля покупателя.
  2. Строка без товара → сообщение у колонки товара.
  3. Количество 0 → сообщение о количестве.
  4. Отрицательная цена → сообщение о цене (если тип её допускает).
  5. Некорректная накладная, кнопка «Записать» → серверная проверка запрещает запись даже без «Проверить».

Сообщение есть, а документ записался — ищем, где не установлен Отказ. Поле не подсвечивается — проверяем путь Поле и индекс строки.

Проверь себя

  1. Почему проверки в форме недостаточно?

  2. Что указывается в Сообщение.Поле: имя элемента или путь к данным?

  3. Для строки с НомерСтроки = 3 — какой путь в Поле?

Ответы
  1. Запись из кода, обработок и обменов проходит без формы.
  2. Путь к данным (Покупатель, Товары[2].Количество).
  3. Товары[2] — индекс с нуля.
