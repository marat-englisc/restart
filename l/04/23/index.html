Программное создание элементов формы

Коротко

Элементы, реквизиты и команды можно создавать кодом на сервере (обычно в ПриСозданииНаСервере): реквизиты — ИзменитьРеквизиты(МассивРеквизитовФормы) одним вызовом, поля и кнопки — Элементы.Добавить(Имя, Тип, Родитель), команды — Команды.Добавить(), обработчики — УстановитьДействие() / Действие. Это нужно, когда состав формы заранее неизвестен; в остальных случаях — редактор.

Пример: в форме накладной создать поле «Учебный комментарий», обработчик его изменения и кнопку «Показать комментарий». Значение живёт только в форме.

Подготовка

  1. В редакторе — обычная группа ГруппаУчебныхЭлементов (заголовок «Учебные элементы»): место для новых элементов.
  2. Имён КомментарийУчебный, ПоказатьКомментарийУчебный, КнопкаКомментарияУчебного в форме ещё нет.
  3. В ПриСозданииНаСервере добавляем вызов ДобавитьУчебныеЭлементы().

Процедуры пишем заранее: Действие и УстановитьДействие лишь связывают событие с существующим кодом.

К динамическому реквизиту обращаемся через ЭтотОбъект.Имя: при проверке модуля он ещё не объявлен, и простое КомментарийУчебный вызвало бы «Переменная не определена».

Порядок и правила

  1. Данные → элемент → команда → кнопка. Поле без ПутьКДанным ничего не покажет.
  2. Все реквизиты — одним вызовом ИзменитьРеквизиты (каждый вызов перестраивает форму). См. раздел 7.9.4 руководства разработчика 1С.
  3. Изменения живут только в текущем экземпляре формы: дерево в Конфигураторе не меняется, при следующем открытии код создаст элементы заново.
  4. Удалять программно можно только программно созданное; обычный элемент скрываем Видимость.

Тот же приём использован в учебной обработке темы 29:

Форма обработки ПрактикумУправляемыхФорм в Конфигураторе почти пуста: таблица, поля и кнопка создаются кодом при открытии.

Модуль этой формы: реквизиты собираются в массив и создаются одним ИзменитьРеквизиты, затем Элементы.Добавить создаёт таблицу, колонки и поле итога.

Комментарий не сохраняется

Реквизит формы не записывается в документ. Для хранения нужен реквизит документа — его создают в Конфигураторе.

Проверка

  1. Переоткрываем накладную → в группе есть поле и кнопка.
  2. Кнопка показывает начальный текст; меняем текст и уходим из поля → сообщение о длине.
  3. Переоткрываем документ → снова начальный текст.

Проверь себя

  1. Почему все новые реквизиты добавляют одним ИзменитьРеквизиты?

  2. Почему к созданному реквизиту обращаются через ЭтотОбъект.?

  3. Сохранится ли созданное поле в Конфигураторе?

Ответы
  1. Каждый вызов перестраивает форму — это дорого.
  2. На этапе компиляции модуля реквизита нет, прямое имя даст ошибку.
  3. Нет, оно существует только в открытом экземпляре формы.
