> [!abstract] Коротко
> **Предопределённый элемент** описан в конфигурации и имеет имя для кода (`Справочники.Склады.ОсновнойСклад`) — его можно переименовать для пользователя, но код продолжит работать. **Значение заполнения** подставляет простое значение по умолчанию, `ОбработкаЗаполнения` — сложное. **Проверка заполнения** делает реквизит обязательным, но не проверяет правильность значения.

## Что это?

**Предопределённый элемент** - элемент справочника, который описан разработчиком в конфигурации и имеет внутреннее имя. Например, в справочнике складов может быть заранее предусмотрен `ОсновнойСклад`.

Обычный элемент создаёт пользователь, и заранее известного разработчику имени у него нет. Предопределённый элемент нужен, когда алгоритм должен обращаться к конкретному элементу независимо от того, как пользователь переименовал его.

## Создание

Открываем нужный справочник, переходим на вкладку **"Прочее"** и открываем **"Предопределённые"**. Добавляем элемент, задаём его имя, код и наименование.

![[22-Предопределенный-элемент.png]]

*Учебный справочник `Склады` в «1С:Купец»: окно «Предопределённые элементы справочника» и диалог нового элемента с именем `ОсновнойСклад`.*

![[22-Список-предопределенных.png]]

*После «ОК» элемент появился в списке: имя для кода, код и наименование для пользователя.*

Имя `ОсновнойСклад` используется в программе. Наименование **"Основной склад"** отображается пользователю. При применении конфигурации и запуске базы предопределённые данные обновляются в соответствии с настройками платформы и конфигурации.

> [!warning] Важно
> Простое создание элемента программным кодом не делает его предопределённым. Признак связан с механизмом предопределённых данных.

## Обращение в коде

Если мы создали справочник `Склады` и предопределённый элемент `ОсновнойСклад`, в серверном коде можем получить ссылку:
```1C
Склад = Справочники.Склады.ОсновнойСклад;
```

На клиенте управляемого приложения для получения такого значения можно использовать:
```1C
Склад = ПредопределенноеЗначение("Справочник.Склады.ОсновнойСклад");
```

Обратите внимание: в строке используется `Справочник` в единственном числе. Это путь к объекту метаданных. `Справочники` во множественном числе - менеджер в программном коде.

## Значение заполнения

У реквизита можно задать **значение заполнения**, которое будет подставляться при создании объекта. Например, для `Количество` - 1, для склада - предопределённый основной склад.

Также есть настройка **"Заполнять из данных заполнения"**. Она позволяет использовать данные, которые переданы при создании объекта. Например, из списка документов с отбором по покупателю.

Если правила сложнее, используем обработчик `ОбработкаЗаполнения`. Его мы уже встречали при вводе на основании. Значение заполнения удобно для простого значения по умолчанию, обработчик - для алгоритма.

## Проверка заполнения

У реквизита можно выбрать **"Проверка заполнения" -> "Выдавать ошибку"**. Это нужно, например, для обязательного покупателя.

![[22-Заполнение-реквизита.png]]

*Палитра свойств реквизита `Покупатель` документа `ЗаказКлиента`: «Заполнять из данных заполнения», «Значение заполнения» и раскрытый список «Проверка заполнения». В учебной базе оставлено значение «Не проверять».*

Однако проверка наличия значения и проверка его правильности - разные задачи. Заполненный договор может принадлежать другому покупателю. Для этого нужна дополнительная проверка при записи.

> [!warning] Важно
> Отбор в поле выбора облегчает ввод, но не гарантирует правильность данных при загрузке или программной записи. Правила, которые должны выполняться всегда, проверяем в серверной логике объекта. Пример есть в [[24. Программная работа с документами]].

## Что проверить

Создаём новый объект и смотрим значение по умолчанию. Меняем его и записываем. Затем создаём ещё один объект: значение по умолчанию должно подставиться заново, а ранее записанный объект должен сохранить выбранное пользователем значение.

> [!question]- Проверь себя
> 1. Как обратиться к предопределённому складу на клиенте?
> 2. Создали элемент кодом с наименованием «Основной склад». Он предопределённый?
> 3. Проверка заполнения «Выдавать ошибку» у договора. Гарантирует ли она, что договор принадлежит покупателю?
>
> > [!success]- Ответы
> > 1. `ПредопределенноеЗначение("Справочник.Склады.ОсновнойСклад")`.
> > 2. Нет. Признак связан только с механизмом предопределённых данных конфигурации.
> > 3. Нет — только что поле не пустое. Принадлежность проверяем кодом при записи.
