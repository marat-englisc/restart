> [!abstract] Коротко
> **Справочник** — список однотипных объектов: товары, сотрудники, контрагенты. Каждый справочник — отдельная таблица базы. У элемента есть **стандартные реквизиты** (Ссылка, Код, Наименование…) и **дополнительные**, которые добавляем сами. Справочник может быть **иерархическим**, **подчинённым** другому (владелец) и иметь **табличные части**.

## Что это такое

**Справочники** хранят данные с одинаковой структурой и списочным характером: список сотрудников, перечень товаров, поставщики и покупатели.

![[Pasted image 20260908232105.png]]

*Пример справочника «Номенклатура»: у каждого элемента есть код, наименование и группа-родитель.*

С точки зрения базы данных каждый справочник — **отдельная таблица**:

![[Pasted image 20260908232240.png]]

*Три справочника — три независимые таблицы с колонками «Код» и «Наименование».*

> [!tip] Именование
> Справочники называем **во множественном числе**: `Номенклатура`, `Сотрудники`, `Контрагенты`. Элемент справочника — в единственном: «Сотрудник», «Контрагент» (это задаётся в представлениях объекта).

## Нумерация

Вкладка **«Нумерация»**:

![[Pasted image 20260909001655.png]]

*Вкладка «Нумерация»: автонумерация, контроль уникальности и серии кодов.*

- **Автонумерация** — новый элемент получает следующий код автоматически. Строковый код длины 9 выглядит как `000000001`.
- **Контроль уникальности** — запрещает два элемента с одинаковым кодом в пределах серии.
- **Серии кодов** — где действует нумерация: во всём справочнике, в пределах группы (подчинения) или в пределах владельца.

> [!warning] Код — не идентификатор
> Код удобен человеку, но элемент однозначно определяет **Ссылка** (внутренний уникальный идентификатор). Код можно изменить, а ссылка у элемента остаётся навсегда.

## Данные: код, наименование, реквизиты

Вкладка **«Данные»**:

![[Pasted image 20260909003820.png]]

*Вкладка «Данные»: длина и тип кода, длина наименования, основное представление, списки реквизитов и табличных частей.*

- **Длина кода** — до 50 символов; **тип кода** — Строка или Число.
- **Длина наименования** — до 150 символов; можно задать 0, если наименование не нужно.
- **Основное представление** — что показывать в полях, где выбран элемент: код или наименование.

> [!warning] Уменьшение длины на живых данных
> Если сократить длину кода или наименования при существующих данных, часть значений может обрезаться, появятся дубли кодов, обновление может не пройти. Проверяем данные и делаем это на копии базы.

### Стандартные реквизиты

Кнопка **«Стандартные реквизиты»** показывает реквизиты, которые платформа создаёт сама:

![[Pasted image 20260909004227.png]]

*Стандартные реквизиты справочника. Серые (Владелец, Родитель, ЭтоГруппа) появятся, когда включим подчинение и иерархию.*

| Реквизит | Тип | Смысл |
| --- | --- | --- |
| `Ссылка` | `СправочникСсылка.Имя` | Уникально указывает на конкретный элемент или группу |
| `Код` | Строка/Число | Пользовательский идентификатор, может заполняться автоматически |
| `Наименование` | Строка | Название элемента |
| `Владелец` | Ссылка на владельца | Элемент справочника-владельца (для подчинённых справочников) |
| `Родитель` | Ссылка на этот же справочник | Группа, в которой лежит элемент |
| `ЭтоГруппа` | Булево | Группа это или обычный элемент |
| `ПометкаУдаления` | Булево | Помечен ли элемент на удаление ([[13. Пометка удаления]]) |
| `Предопределенный` | Булево | Создан ли элемент как предопределённый в конфигурации ([[22. Предопределённые данные и заполнение]]) |
| `ИмяПредопределенныхДанных` | Строка | Внутреннее имя предопределённого элемента |

Стандартным реквизитам можно задать свой синоним: ПКМ по реквизиту → **Свойства**:

![[Pasted image 20260909124358.png]]

*Свойства стандартного реквизита: для `Родитель` задан синоним «Номенклатурная группа».*

### Дополнительные реквизиты

Если стандартных реквизитов мало, добавляем свои в группу **«Реквизиты»** на вкладке «Данные» — для каждого задаём имя, синоним и тип:

![[Pasted image 20260909155412.png]]

*Добавлен реквизит `ВидНоменклатуры` типа Строка(10). Позже заменим его тип на перечисление.*

На вкладке **«Представление»** свойств реквизита настраивается поведение поля ввода:

![[Pasted image 20260909161637.png]]

*Свойства реквизита на вкладке «Представление»: режим пароля, подсказка, маска, многострочный режим, проверка заполнения.*

| Свойство | Что делает |
| --- | --- |
| **Режим пароля** | Вводимые символы скрываются звёздочками |
| **Подсказка** | Поясняющий текст к полю |
| **Маска** | Шаблон ввода, например для телефона |
| **Многострочный режим** | Ввод длинного текста в несколько строк |
| **Проверка заполнения** | «Выдавать ошибку» — реквизит становится обязательным |

## Табличная часть

**Табличная часть** хранит данные, структура которых одинакова у всех элементов, а количество строк — разное. Например, у сотрудника — места предыдущей работы:

![[Pasted image 20260909203227.png]]

*У сотрудника Платформова И.И. две строки стажа.*

В базе табличная часть — **отдельная таблица**, связанная с элементом полем `Ссылка`:

![[Pasted image 20260909203347.png]]

*Таблица табличной части `СтажРаботы`: по полю `Ссылка` строки связаны с сотрудником, `НомерСтроки` задаёт порядок.*

Создание: вкладка «Данные» → в нижнем списке **«Табличные части» → Добавить** → задаём имя → добавляем реквизиты табличной части:

![[Pasted image 20260909204122.png]]

*Табличная часть `СтажРаботы` справочника «Сотрудники» с реквизитами организации и дат; у даты увольнения «Состав даты» = Дата.*

У типа **Дата** три варианта состава: **Дата** (день, месяц, год), **Время** (часы, минуты, секунды), **Дата и время**.

## Иерархия

Чтобы список не был одной длинной простынёй, включаем иерархию на вкладке **«Иерархия»**:

![[Pasted image 20260909112211.png]]

*Вкладка «Иерархия»: иерархия групп и элементов, группы сверху, без ограничения уровней.*

| Настройка | Варианты и смысл |
| --- | --- |
| **Вид иерархии** | *Иерархия групп и элементов* — есть «папки»-группы, а в них элементы. *Иерархия элементов* — элемент может быть родителем другого элемента (например, подразделения) |
| **Размещать группы сверху** | Группы выводятся над элементами, а не вперемешку |
| **Ограничение количества уровней** | Максимальная глубина вложенности |

После включения у справочника появляются стандартные реквизиты `Родитель` и `ЭтоГруппа` (последний — только при иерархии групп и элементов).

## Подчинённый справочник (владельцы)

Связь «один ко многим» между справочниками задаётся вкладкой **«Владельцы»**. Например, у контрагента много договоров, и договор без контрагента не существует. Открываем **подчинённый** справочник (`Договоры`) → «Владельцы» → карандаш → отмечаем владельца:

![[Pasted image 20260909132954.png]]

*Справочник «Договоры» подчинён справочнику «Контрагенты».*

После этого в стандартных реквизитах появится `Владелец` — ему удобно дать понятный синоним:

![[Pasted image 20260909133418.png]]

*Стандартный реквизит `Владелец` с синонимом «Контрагент».*

> [!info] Владелец или обычный реквизит?
> Обычный реквизит типа `СправочникСсылка.Контрагенты` просто хранит ссылку. **Владелец** делает элемент частью другого объекта: список договоров открывается с отбором по контрагенту, коды могут нумероваться в пределах владельца, без владельца элемент записать нельзя.

## Поле ввода

Вкладка **«Поле ввода»** определяет, как элементы справочника выбираются в полях других объектов:

![[Pasted image 20260909134553.png]]

*Настройки поля ввода справочника «Договоры»: создание при вводе, ввод по наименованию и коду с поиском по началу строки.*

| Настройка | Что делает |
| --- | --- |
| **Быстрый выбор** | Выбор из выпадающего списка вместо открытия формы выбора. Удобно для коротких справочников |
| **Создание при вводе** | Можно создать новый элемент прямо из поля, если введённого значения нет |
| **Ввод по строке** | По каким полям ищем при наборе текста (наименование, код) |
| **Способ поиска строки** | С начала строки или любое вхождение |
| **Полнотекстовый поиск** | Использовать полнотекстовый индекс — поиск по словам, а не только по совпадению строки |
| **Режим получения данных выбора** | Непосредственно или в фоне: фоновый режим не блокирует интерфейс на время подбора подсказок |
| **История выбора при вводе** | Запоминать ранее выбранные значения и предлагать их первыми |

> [!warning] Важно
> Если удалили стандартное поле «Наименование» (длина 0), его нужно убрать и из «Ввода по строке».

> [!question]- Проверь себя
> 1. Чем `Код` отличается от `Ссылка`?
> 2. Где хранятся строки табличной части и как они связаны с элементом?
> 3. Когда выбрать «Владельца», а когда обычный ссылочный реквизит?
> 4. Какое свойство делает реквизит обязательным?
>
> > [!success]- Ответы
> > 1. Код — пользовательский, изменяемый, может повторяться. Ссылка — внутренний уникальный идентификатор, не меняется.
> > 2. В отдельной таблице; связь — по полю `Ссылка`, порядок — `НомерСтроки`.
> > 3. Владелец — когда подчинённый объект не существует без владельца (договор контрагента). Обычный реквизит — для простой связи («основной менеджер»).
> > 4. «Проверка заполнения» = «Выдавать ошибку».
