> [!abstract] Коротко
> **Расширение** — отдельный «слой» доработок поверх типовой конфигурации: свои объекты и **заимствованные** объекты основной конфигурации, в которые добавляем реквизиты, формы и код. Методы перехватываем аннотациями: `&Перед`, `&После`, `&Вместо` (+ `ПродолжитьВызов()`), `&ИзменениеИКонтроль` (точечные `#Вставка`/`#Удаление`). Имена своих объектов и методов — с **префиксом** расширения. Основная конфигурация остаётся на поддержке; после обновления всё равно проверяем применимость расширения и его сценарии.

## Когда расширение, а когда правка конфигурации

| Ситуация | Решение |
| --- | --- |
| Типовая на поддержке, нужна доработка | **Расширение** — стандарт де-факто |
| Своя конфигурация, полный контроль | Правим основную конфигурацию |
| Нужно изменить структуру типового объекта | Расширение умеет добавлять реквизиты, табличные части, формы; удалять/менять типовые — нет |

## Создание расширения

**Конфигурация → Расширения конфигурации → Добавить**:

![[27-Расширения-конфигурации.png]]

*Окно расширений и диалог нового расширения: имя, синоним, префикс, назначение.*

| Поле | Пример | Зачем |
| --- | --- | --- |
| Имя | `КупецДоработки` | Идентификатор расширения |
| Префикс | `Куп_` | Добавляется к именам своих объектов и методов — не будет конфликтов с типовыми |
| Назначение | Адаптация | Исправление / Адаптация / Дополнение |

Открываем расширение (**Действия → Открыть конфигурацию**) — появится отдельное дерево.

## Заимствование объекта

В дереве **основной** конфигурации: ПКМ по `РасходнаяНакладная` → **Добавить в расширение** (`Alt+Shift+F2`). В дереве расширения объект появится как заимствованный. Теперь можно:

- добавить ему **свой реквизит** `Куп_Комментарий`;
- заимствовать его **форму** и вывести поле;
- заимствовать **модуль** и перехватить методы.

> [!warning] Режим контроля свойств
> У заимствованного объекта по умолчанию проверяется, что его свойства в основной конфигурации не изменились. Если поставщик поменял объект, расширение предупредит при обновлении. Это полезно — не отключаем без причины.

## Аннотации перехвата

Открываем модуль объекта заимствованного документа и пишем методы с аннотацией. Имя своего метода — любое (принято с префиксом), имя перехватываемого — в скобках.

### `&Перед` — выполнить до

```1C
&Перед("ПередЗаписью")
Процедура Куп_ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)

	Если НЕ Отказ И Товары.Количество() = 0 И Услуги.Количество() = 0 Тогда
		Сообщение = Новый СообщениеПользователю;
		Сообщение.Текст = "Добавьте хотя бы один товар или услугу";
		Сообщение.Поле = "Товары";
		Сообщение.УстановитьДанные(ЭтотОбъект);
		Сообщение.Сообщить();
		Отказ = Истина;
	КонецЕсли;

КонецПроцедуры
```

Сначала выполнится наш метод, затем типовой `ПередЗаписью`. Если мы установили `Отказ`, типовой код всё равно выполнится (с `Отказ = Истина`) — запись не произойдёт.

### `&После` — выполнить после

```1C
&После("ОбработкаЗаполнения")
Процедура Куп_ОбработкаЗаполнения(ДанныеЗаполнения, СтандартнаяОбработка)
	Если НЕ ЗначениеЗаполнено(Куп_Комментарий) Тогда
		Куп_Комментарий = "Создан " + Формат(ТекущаяДатаСеанса(), "ДЛФ=D");
	КонецЕсли;
КонецПроцедуры
```

### `&Вместо` — заменить

```1C
&Вместо("ПересчитатьСуммыТоваров")
Процедура Куп_ПересчитатьСуммыТоваров()

	ПродолжитьВызов();           // выполнить исходный метод (можно не вызывать)
	Для Каждого Строка Из Товары Цикл
		Строка.Сумма = Окр(Строка.Сумма * 0.95, 2);   // наша скидка 5%
	КонецЦикла;
	ИтоговаяСумма = Товары.Итог("Сумма") + Услуги.Итог("Сумма");

КонецПроцедуры
```

`ПродолжитьВызов()` вызывает исходный метод (и перехваты других расширений). Если его не вызвать — исходный код не выполнится вовсе. Для функций: `Результат = ПродолжитьВызов(параметры)`.

Метод `ПересчитатьСуммыТоваров` должен существовать в исходном модуле и каждый раз считать сумму **от количества и цены**, а не от прежней суммы. Иначе повторный вызов применит скидку ещё раз. После скидки пересчитываем `ИтоговаяСумма` с учётом товаров и услуг. Два показанных способа изменения одного метода — альтернативы: одновременно их не подключаем.

### `&ИзменениеИКонтроль` — точечная правка

Копируем текст исходного метода и помечаем изменения:

```1C
&ИзменениеИКонтроль("ПересчитатьСуммыТоваров")
Процедура Куп_ПересчитатьСуммыТоваров()
	Для Каждого СтрокаТовара Из Товары Цикл
		#Удаление
		СтрокаТовара.Сумма = Окр(СтрокаТовара.Количество * СтрокаТовара.Цена, 2);
		#КонецУдаления
		#Вставка
		СтрокаТовара.Сумма = Окр(СтрокаТовара.Количество * СтрокаТовара.Цена * 0.95, 2);
		#КонецВставки
	КонецЦикла;
КонецПроцедуры
```

Платформа **контролирует**, что исходный текст не изменился: если поставщик в обновлении поменял метод, расширение перестанет применяться с понятной ошибкой — вы увидите, что правку нужно пересмотреть.

| Аннотация | Когда применять |
| --- | --- |
| `&Перед` / `&После` | Добавить логику, не трогая исходную — **предпочтительно** |
| `&Вместо` + `ПродолжитьВызов()` | Обернуть или заменить метод целиком |
| `&ИзменениеИКонтроль` | Нужно изменить середину метода; изменение исходника будет замечено |

## Формы в расширении

Заимствуем форму → в редакторе добавляем свои элементы и команды → в модуле формы перехватываем обработчики теми же аннотациями, например `&После("ПриСозданииНаСервере")`. Элемент типовой формы можно скрыть, но не удалить.

## Применение и отладка

1. **Конфигурация → Обновить конфигурацию базы данных** для расширения (из его окна) — `F7`.
2. Новые сеансы получат расширение; открытые — после перезапуска.
3. Отладка — как обычно: точка останова в модуле расширения.
4. Выгрузка — файл `.cfe`; загрузка на рабочую базу — **Расширения конфигурации → Загрузить** (или через Предприятие: «Администрирование → Расширения» в типовых).

> [!warning] Безопасный режим и защита от опасных действий
> Расширение, загруженное **в Предприятии**, по умолчанию работает в **безопасном режиме** (нет доступа к файлам, COM, внешним компонентам) и может требовать подтверждения. Если доработке нужен такой доступ — отключение безопасного режима решает администратор осознанно.

## Ограничения

- Нельзя удалить или переименовать типовой реквизит, изменить его тип.
- Собственные данные расширения (свои справочники, реквизиты) удалятся вместе с ним — перед удалением делаем `.dt`.
- После обновления типовой конфигурации проверяем, применяется ли расширение и работают ли перехваченные сценарии ([[01. Основы конфигурирования/27. Сравнение, поддержка и расширения|27. Сравнение, поддержка и расширения]]).

> [!question]- Проверь себя
> 1. Чем `&Перед` безопаснее `&Вместо`?
> 2. Что будет, если в `&Вместо` не вызвать `ПродолжитьВызов()`?
> 3. Зачем нужен префикс расширения?
> 4. Поставщик изменил метод, перехваченный через `&ИзменениеИКонтроль`. Что произойдёт?
>
> > [!success]- Ответы
> > 1. Исходный код выполняется в любом случае — меньше шанс сломать типовую логику при обновлении.
> > 2. Исходный метод не выполнится.
> > 3. Чтобы имена своих объектов и методов не пересеклись с объектами конфигурации и других расширений.
> > 4. Расширение не применится, платформа сообщит о расхождении — правку нужно перенести на новый текст метода.
