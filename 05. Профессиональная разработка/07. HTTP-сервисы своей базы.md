> [!abstract] Коротко
> **HTTP-сервис** — объект конфигурации, который делает базу 1С REST-сервером: **корневой URL** → **шаблоны URL** (`/stock/{code}`) → **методы** (GET, POST…) → функция-обработчик `(Запрос) → HTTPСервисОтвет`. База публикуется на веб-сервере (IIS/Apache), адрес вызова: `http://сервер/имя_публикации/hs/корневой_url/шаблон`. Код выполняется на сервере с правами пользователя, под которым идёт подключение.

## Создание

**Общие → HTTP-сервисы → Добавить**:

![[Картинки/05. Профессиональная разработка/07-Добавить-HTTP-сервис.png]]

*Ветка `HTTP-сервисы` в Конфигураторе и команда «Добавить». В исходной «1С:Купец» ветка пуста: `СкладAPI` предстоит создать по таблицам ниже. Это не ветка `Web-сервисы` — та предназначена для SOAP.*

| Свойство | Пример |
| --- | --- |
| Имя | `СкладAPI` |
| Корневой URL | `stock` |
| Повторное использование сеансов | Использовать (быстрее при частых вызовах) |

Вкладка **Шаблоны URL → Добавить**:

| Шаблон | Шаблон URL | Метод | Обработчик |
| --- | --- | --- | --- |
| `Остаток` | `/balance/{code}` | GET | `ОстатокGET` |
| `Заказ` | `/orders` | POST | `ЗаказPOST` |

`{code}` — параметр пути, его значение придёт в `Запрос.ПараметрыURL["code"]`.

## Обработчик GET

Модуль HTTP-сервиса:

```1C
Функция ОстатокGET(Запрос)

	КодТовара = Запрос.ПараметрыURL["code"];
	Товар = Справочники.Номенклатура.НайтиПоКоду(КодТовара);
	Если Товар.Пустая() Тогда
		Возврат ОтветJSON(404, Новый Структура("error", "Товар не найден"));
	КонецЕсли;

	ЗапросОстатков = Новый Запрос(
	"ВЫБРАТЬ
	|	ЕСТЬNULL(СУММА(О.КоличествоОстаток), 0) КАК Остаток
	|ИЗ
	|	РегистрНакопления.ТоварыНаСкладах.Остатки(, Номенклатура = &Товар) КАК О");
	ЗапросОстатков.УстановитьПараметр("Товар", Товар);
	Остаток = ЗапросОстатков.Выполнить().Выгрузить()[0].Остаток;

	Возврат ОтветJSON(200, Новый Структура("code,name,balance", КодТовара, Товар.Наименование, Остаток));

КонецФункции

Функция ОтветJSON(КодСостояния, Данные)

	Запись = Новый ЗаписьJSON;
	Запись.УстановитьСтроку();
	ЗаписатьJSON(Запись, Данные);

	Ответ = Новый HTTPСервисОтвет(КодСостояния);
	Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
	Ответ.УстановитьТелоИзСтроки(Запись.Закрыть(), КодировкаТекста.UTF8, ИспользованиеByteOrderMark.НеИспользовать);
	Возврат Ответ;

КонецФункции
```

| Источник данных запроса | Как получить |
| --- | --- |
| Параметр пути `{code}` | `Запрос.ПараметрыURL["code"]` |
| Параметр строки `?warehouse=…` | `Запрос.ПараметрыЗапроса.Получить("warehouse")` |
| Заголовок | `Запрос.Заголовки.Получить("Authorization")` |
| Тело (POST) | `Запрос.ПолучитьТелоКакСтроку()` → `ПрочитатьJSON` |

## Обработчик POST — создать документ

```1C
Функция ЗаказPOST(Запрос)

	Попытка
		Чтение = Новый ЧтениеJSON;
		Чтение.УстановитьСтроку(Запрос.ПолучитьТелоКакСтроку());
		Данные = ПрочитатьJSON(Чтение, Истина);
		Чтение.Закрыть();
	Исключение
		Возврат ОтветJSON(400, Новый Структура("error", "Некорректный JSON"));
	КонецПопытки;

	// Проверяем данные: обязательные поля, типы, существование товаров...
	// Создаём документ через серверную функцию (как в практике раздела 02)
	// После реализации создания: 201 и номер документа либо 422 при ошибке данных.
	// Пока создания нет, явно сообщаем, что операция не реализована.
	Возврат ОтветJSON(501, Новый Структура("error", "Создание заказа ещё не реализовано"));

КонецФункции
```

Это **каркас POST**, а не готовая загрузка заказов: он возвращает `400` для некорректного JSON и `501` для разбираемого JSON. Перед заменой последнего `Возврат` проверьте тип корневого значения, обязательные поля, права и повторную отправку одного заказа. Обработчик должен возвращать `HTTPСервисОтвет` на каждом пути выполнения.

Код ответа — часть контракта: `200` — ок, `201` — создано, `400` — плохой запрос, `401/403` — нет доступа, `404` — не найдено, `422` — данные не прошли проверку, `500` — ошибка сервера.

## Публикация и вызов

1. Нужен веб-сервер (IIS или Apache) и установленный модуль расширения веб-сервера 1С.
2. Конфигуратор (запущенный от администратора ОС) → **Администрирование → Публикация на веб-сервере** → имя публикации `kupets`, флажок **«Публиковать HTTP-сервисы»**.
3. Вызов:

```bash
curl -u "Пользователь:Пароль" http://localhost/kupets/hs/stock/balance/000000001
```

Ответ: `{"code":"000000001","name":"Чайник \"Победа\"","balance":7}`.

> [!warning] Безопасность
> - Подключение идёт под **пользователем 1С**, определённым настройками аутентификации публикации. Заголовок `Bearer` сам по себе не реализует вход по произвольному токену: такой способ требует отдельного механизма проверки. Для интеграции нужен пользователь с правами только на нужные объекты.
> - Публикуем по HTTPS.
> - Не доверяем входным данным: проверяем типы, длины, существование ссылок.
> - Не возвращаем подробный текст исключения наружу — пишем его в журнал регистрации, клиенту — краткое сообщение.

## Отладка

**Отладка → Подключение → Автоматическое подключение** → отметить **HTTP-сервисы** (или «Сеансы HTTP-сервисов»). Ставим точку останова в обработчике и вызываем сервис через `curl` или Postman.

> [!question]- Проверь себя
> 1. Как будет выглядеть URL для шаблона `/balance/{code}` при публикации `kupets` и корневом URL `stock`?
> 2. Чем `ПараметрыURL` отличаются от `ПараметрыЗапроса`?
> 3. Под какими правами выполняется код сервиса?
>
> > [!success]- Ответы
> > 1. `http://сервер/kupets/hs/stock/balance/<код>`.
> > 2. `ПараметрыURL` — части пути из шаблона (`{code}`), `ПараметрыЗапроса` — параметры после `?`.
> > 3. С правами пользователя 1С, под которым выполнена аутентификация.
