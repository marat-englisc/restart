> [!abstract] Коротко
> XML пишут потоково `ЗаписьXML` (`ЗаписатьНачалоЭлемента` → `ЗаписатьАтрибут` → `ЗаписатьТекст` → `ЗаписатьКонецЭлемента`) и читают `ЧтениеXML` в цикле `Пока Чтение.Прочитать()` по `ТипУзла`. Для объектов 1С есть сериализация XDTO (`СериализаторXDTO`). Регулярный обмен между базами строят на **планах обмена** и готовых механизмах (Конвертация данных, EnterpriseData), а не на «ручной выгрузке».

## Запись XML

```1C
// На сервере: выгрузка товаров в файл
Запись = Новый ЗаписьXML;
Запись.ОткрытьФайл(ПутьКФайлу, "UTF-8");      // или Запись.УстановитьСтроку() — в строку
Запись.ЗаписатьОбъявлениеXML();
Запись.ЗаписатьНачалоЭлемента("Товары");
Запись.ЗаписатьАтрибут("Дата", XMLСтрока(ТекущаяДатаСеанса()));

Выборка = Справочники.Номенклатура.Выбрать();
Пока Выборка.Следующий() Цикл
	Если Выборка.ЭтоГруппа Тогда
		Продолжить;
	КонецЕсли;
	Запись.ЗаписатьНачалоЭлемента("Товар");
	Запись.ЗаписатьАтрибут("Код", Выборка.Код);
	Запись.ЗаписатьТекст(Выборка.Наименование);
	Запись.ЗаписатьКонецЭлемента();
КонецЦикла;

Запись.ЗаписатьКонецЭлемента();
Запись.Закрыть();
```

Результат:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Товары Дата="2026-10-19T15:00:00">
	<Товар Код="000000001">Чайник "Победа"</Товар>
	...
</Товары>
```

`XMLСтрока()` даёт каноническое представление значения (дата — ISO, число — с точкой, булево — `true/false`); обратно — `XMLЗначение(Тип("Дата"), Строка)`.

## Чтение XML

```1C
Чтение = Новый ЧтениеXML;
Чтение.ОткрытьФайл(ПутьКФайлу);

Пока Чтение.Прочитать() Цикл
	Если Чтение.ТипУзла = ТипУзлаXML.НачалоЭлемента И Чтение.Имя = "Товар" Тогда
		Код = Чтение.ЗначениеАтрибута("Код");
		Чтение.Прочитать();                          // переходим к текстовому узлу
		Наименование = Чтение.Значение;
		// ... найти или создать товар по коду
	КонецЕсли;
КонецЦикла;

Чтение.Закрыть();
```

`ЧтениеXML` — курсор: `Прочитать()` переходит к следующему узлу (начало элемента, текст, конец элемента). Так читается файл любого размера без загрузки целиком в память.

Показанный читатель рассчитан только на простой формат `<Товар Код="…">текст</Товар>` из примера записи. Для произвольного XML одного `Прочитать()` недостаточно: текст может быть разбит на несколько узлов, а элемент — пустым или вложенным. В рабочем загрузчике накапливайте текст до соответствующего конца элемента и проверяйте атрибуты перед созданием объекта.

> [!tip] DOM для небольших файлов
> Для небольших документов удобнее модель DOM: `ПостроительDOM.Прочитать(Чтение)` → `ДокументDOM` → поиск через `ПолучитьЭлементыПоИмени()`. Для больших — только потоковое чтение.

## XDTO: объекты 1С ↔ XML

```1C
// Выгрузить объект целиком (с реквизитами и табличными частями)
Запись = Новый ЗаписьXML;
Запись.УстановитьСтроку();
СериализаторXDTO.ЗаписатьXML(Запись, Ссылка.ПолучитьОбъект());
ТекстXML = Запись.Закрыть();

// Прочитать обратно в объект (в базе с такой же структурой)
Чтение = Новый ЧтениеXML;
Чтение.УстановитьСтроку(ТекстXML);
Объект = СериализаторXDTO.ПрочитатьXML(Чтение);
```

Так устроена выгрузка «один в один» между базами с одинаковой конфигурацией. Для обмена по чужой схеме (XSD от партнёра) импортируют **XDTO-пакет** (Общие → XDTO-пакеты) и работают с объектами `ФабрикаXDTO`.

![[Картинки/05. Профессиональная разработка/08-Импорт-XDTO.png]]

*Контекстное меню ветки `XDTO-пакеты`: «Импорт XML-схемы…» — точка входа для схемы XSD партнёра. Для потокового чтения простого XML из начала темы импорт XSD не требуется.*

`ПрочитатьXML` восстанавливает значение в памяти, а не сохраняет объект в базе. После чтения нужны сопоставление ссылок, проверки и явная запись; одинаковая структура конфигураций сама по себе не гарантирует наличие объектов, на которые ссылается XML.

## Правила загрузки данных

| Правило | Почему |
| --- | --- |
| Сопоставление по **ключу** (код, ИНН, GUID), а не по наименованию | Наименования не уникальны |
| Повторная загрузка не создаёт дубли | Сначала ищем существующий объект |
| Проверка значений до записи | Отрицательное количество, неизвестный товар |
| Порция + транзакция на порцию | Ошибка в одной записи не «роняет» всю загрузку и не держит длинную транзакцию |
| Протокол | Что загружено, что пропущено и почему |
| `ОбменДанными.Загрузка = Истина` при массовой загрузке | Устанавливает признак загрузки. Прикладные проверки пропускаются, только если сами обработчики и подписки проверяют этот признак; целостность загружаемых данных обеспечивает вызывающий код |

Флаг **не отключает произвольный код автоматически**. Типичный обработчик сам делает ранний выход `Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;`. Это правило и ответственность загрузчика описаны в [стандарте 1С](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_Development_Standards/Creating_and_modifying_metadata_objects/Object_event_handlers/DataExchange.Load_flag_in_object_event_handlers/).

## Обмен между базами

| Механизм | Для чего |
| --- | --- |
| **План обмена** | Узлы обмена и регистрация изменений: какие объекты изменились с прошлой выгрузки |
| **Конвертация данных** (КД 2/3) | Правила преобразования между разными конфигурациями |
| **EnterpriseData** | Универсальный формат обмена типовых конфигураций 1С |
| HTTP-сервисы / REST | Онлайн-обмен с сайтами и внешними системами ([[07. HTTP-сервисы своей базы]]) |

Junior-разработчику чаще всего достаются доработки готовых правил обмена в типовых конфигурациях — поэтому важно понимать регистрацию изменений и сопоставление объектов, а не писать обмен с нуля.

> [!question]- Проверь себя
> 1. Почему XML большого размера читают `ЧтениеXML`, а не DOM?
> 2. Как избежать дублей при повторной загрузке?
> 3. Зачем нужен план обмена, если можно просто выгрузить все товары?
>
> > [!success]- Ответы
> > 1. Потоковое чтение не загружает документ целиком в память.
> > 2. Искать существующий объект по устойчивому ключу (код, GUID) перед созданием.
> > 3. Он регистрирует изменения — выгружаются только изменённые объекты, и известно, что уже передано.
