> [!abstract] Коротко
> Фирма 1С публикует **стандарты разработки** ([its.1c.ru/db/v8std](https://its.1c.ru/db/v8std)) — по ним проверяют код на ревью и в АПК. Главное для junior: понятные имена, структура модуля по областям, комментарии к экспортным методам, **никаких запросов в цикле**, минимум серверных вызовов, правила — в модуле объекта, `Отказ` не сбрасывать, привилегированный режим — точечно. Ниже — выжимка и чек-лист перед сдачей задачи.

## Имена и оформление

| Правило | Плохо | Хорошо |
| --- | --- | --- |
| Осмысленные имена в ВерблюжьемРегистре | `с`, `тз1`, `сумма_итог` | `СуммаДокумента`, `ТаблицаТоваров` |
| Без сокращений и транслита | `КолВо`, `Tovar` | `Количество`, `Товар` |
| Функция — существительное/вопрос, процедура — глагол | `Функция Посчитать()` | `Функция СуммаСтроки()`, `Процедура ЗаполнитьТовары()` |
| Булево — утверждение | `Флаг` | `ЕстьОшибки`, `ЭтоНовый` |
| Ключевые слова — как в Синтакс-помощнике | `КОНЕЦЕСЛИ`, `конецесли` | `КонецЕсли` |
| Отступы — табуляция; используем команду форматирования своего редактора | | Горячая клавиша зависит от редактора и раскладки команд |
| Длина строки — до ~120 символов, длинные вызовы переносим | | |

## Структура и комментарии

Модуль размечен областями ([[02. Программирование/14. Области в модулях|14. Области в модулях]]). У каждого **экспортного** метода — комментарий-описание в формате, который понимает Конфигуратор/EDT:

```1C
// Рассчитывает сумму строки с округлением до копеек.
//
// Параметры:
//  Количество - Число - количество товара.
//  Цена       - Число - цена за единицу.
//
// Возвращаемое значение:
//  Число - сумма строки.
//
Функция СуммаСтроки(Количество, Цена) Экспорт
	Возврат Окр(Количество * Цена, 2);
КонецФункции
```

Внутри методов комментируем **зачем**, а не что: `// Услуги не учитываем — их нет на складе`, а не `// цикл по товарам`.

## Производительность

| Правило | Почему |
| --- | --- |
| **Нет запросов в цикле** | 1000 строк = 1000 обращений к базе. Собираем данные одним запросом / временной таблицей |
| Нет `ПолучитьОбъект()` в цикле только ради чтения | Читаем запросом нужные поля |
| Обращение через точку `Ссылка.Реквизит` — осторожно | Читает объект целиком; в запросах длинные цепочки — неявные соединения |
| Один серверный вызов на действие пользователя | Каждый вызов — сеть и сериализация формы |
| `&НаСервереБезКонтекста` вместо `&НаСервере`, если не нужна форма | Не передаём данные формы |
| Отборы — в параметры виртуальных таблиц | Платформа считает меньше |
| Транзакции и блокировки — короткие | Иначе ожидания и конфликты у других пользователей |

## Надёжность

| Правило | Почему |
| --- | --- |
| Обязательные правила — в модуле объекта или подписке, а не только в форме | Запись бывает без формы |
| `Отказ = Истина` вместо `Возврат`, `Отказ = Ложь` не писать | Не отменяем чужие проверки |
| Нет пустых `Исключение … КонецПопытки` | Ошибка «проглатывается» |
| `Попытка` — вокруг операции, которая может упасть (сеть, файл), а не вместо проверок | Условие дешевле и понятнее |
| `НачатьТранзакцию()` — перед `Попытка`, откат в `Исключение` + `ВызватьИсключение` | Каноничный шаблон транзакции |
| Сообщения пользователю — понятным языком, технические детали — в журнал регистрации | |
| Внешние вызовы (HTTP, файлы, почта) — не в транзакции | Откат не отменит внешнее действие |

## Безопасность

- Привилегированный режим и общий модуль «Привилегированный» — только точечно, без входных данных «как есть» с клиента.
- Тексты запросов не собираем конкатенацией с пользовательскими значениями — только параметры.
- Пароли и токены не храним в коде и константах «для всех».
- Внешние обработки и `Выполнить()`/`Вычислить()` с пользовательским кодом — не используем.

## Чек-лист перед сдачей задачи

![[Картинки/05. Профессиональная разработка/11-Проверка-конфигурации.png]]

*«Конфигурация → Проверка конфигурации…»: в учебной базе отмечены логическая целостность, некорректные ссылки и синтаксис для тонкого клиента и сервера. Выберите также другие контексты, в которых используется ваш код. Это окно параметров, а не результат проверки: запуск выполняется кнопкой «ОК».*

Синтаксическая проверка не доказывает правильность остатков, прав или обмена: для них нужны сценарии ниже и протокол из итогового проекта.

- [ ] Синтаксическая проверка модуля (`Ctrl+F7`) и **Конфигурация → Проверка конфигурации** без новых ошибок.
- [ ] Сценарий из задачи проверен в Предприятии: успешный путь, отмена, пустые значения, ошибочные данные.
- [ ] Повторное проведение и отмена проведения дают правильные движения.
- [ ] Проверено под **пользователем с рабочей ролью**, а не под администратором.
- [ ] Нет запросов в цикле, лишних серверных вызовов, отладочных `Сообщить()`.
- [ ] Экспортные методы прокомментированы, модуль размечен областями, правки в типовой размечены `// ++ / // --`.
- [ ] Изменение помещено в хранилище/ветку с понятным комментарием и номером задачи.

> [!question]- Проверь себя
> 1. Почему запрос в цикле — грубая ошибка, даже если «работает быстро» на тестовой базе?
> 2. Что писать в комментарии внутри метода?
> 3. Почему проверка под администратором ничего не доказывает?
>
> > [!success]- Ответы
> > 1. Время растёт линейно с числом строк; на рабочих объёмах это сотни и тысячи обращений к базе.
> > 2. Причину решения («зачем»), а не пересказ кода.
> > 3. У администратора есть все права — ошибки ролей и RLS не проявятся.
